* DONE add relative AM and FM
Currently, the per-timbre am and fm frequencies
(the 'timbres' element in the rig)
are absolute hz values -- they disregard the voice's pitch.
Let's rename them:
  am_depth -> abs_am_depth
  am_hz -> abs_am_hz
  fm_depth -> abs_fm_depth
  fm_hz -> abs_fm_hz
And then let's add new relative equivalents:
  am_depth -> rel_am_depth
  am_hz -> rel_am_freq
  fm_depth -> rel_fm_depth
  fm_hz -> rel_fm_freq

These will be independent parameters --
they can both apply to the same voice.
(It's expected that abs will be slow and relative fast,
but nothing enforces that.)

Relative frequencies are relative to the voice's pitch:
0 means off, 1 means sweep all the way from 2*freq to 0*freq,
etc. Note that the synths supposedly permit through-zero FM;
this will actually make that reachable.
** DONE claude: built (2026-07-18). Choices where the spec was loose:
- Renames as specified, except =fm_depth_cents= kept its unit:

  (=am_shape= keeps its name -- it morphs only the abs tremolo's LFO;

- Semantics of the new pair (independent of abs; both multiply in):
  - =rel_am_freq= / =rel_fm_freq=: LFO rate as a unitless multiple of the
    voice's pitch (1 = audio-rate at the pitch). 0 = off; default 1.0,
    inert while the depth is 0 (mirroring the abs defaults).
  - =rel_fm_depth=: *linear* FM, peak deviation as a multiple of the
    voice's pitch -- 1 sweeps 2f..0, and > 1 goes through zero (the
    oscillator core already ran backward; now it's reachable). Validated
    >= 0, deliberately unbounded above.
  - =rel_am_depth=: 0..=1 like the abs depth (amplitude has no pitch to
    be relative to; the *rate* is what's relative).
  - Rates track the voice's *current* (glided) unmodulated pitch -- no
    FM-feedback loop.
- Audio-rate rel AM/FM makes sidebands: give the =cpal_synth= sink
  =oversample = 4= or they alias (the oversampling path existed for
  exactly this). The shipped rigs' rel params default to off, so nothing
  sounds different until you set them.
- The looper's on-grid timbre editor still edits only the abs pair
  (same reasoning as the am_hz rename commit: its rows are a separate,
  non-rig-facing cluster).
- Renamed keys everywhere they appear: rig.rs (+ validation, tests),
  both shipped rigs, the mock, rigs/README.org, both readmes' mentions,
  and the historical notes that the previous rename commit also kept
