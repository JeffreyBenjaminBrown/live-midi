#+TITLE: monome/ — grid synth + hard-won ops notes

This directory contains a tiny Rust synth driven by a monome grid,
plus the scripts and notes from resurrecting Jeff's monome on NixOS
in April 2026.

* Architecture

#+begin_example
  monome USB ─── ftdi_sio ──┐  host NixOS
                            │
                            ▼
          /dev/ttyUSBN  (owned root:dialout)
                            │
                            ▼
              serialoscd  (user systemd service)
              detector @ :12002
              device    @ :PORT   ← assigned per connect; changes!
                            ▲
                            │  OSC/UDP
                            │
    ┌───────────────────────┴────────────────────────┐
    │   docker container (--network host, so        │
    │   localhost in container == localhost on host) │
    │                                                 │
    │    grid_synth  (this repo)                      │
    │      - listens on :9000 for grid events         │
    │      - cpal → /run/user/1000/pipewire-0         │
    │        (socket mounted from host)               │
    │      - /dev/snd bind-mounted; audio group added │
    └─────────────────────────────────────────────────┘
#+end_example

The container is started by =../docker.sh=. Relevant flags:
=--network host= (localhost passthrough), the =pipewire-0= bind
mount, =/dev/snd= device, and =--group-add audio=.

* Running grid_synth

Inside the container:

#+begin_src bash
cd /home/ubuntu/monome
bash ./11-grid-synth.sh [FUND [EDO [X_STEP [Y_STEP]]]]
#+end_src

Args default to =220 46 9 1= — i.e. =(0,0) = 220 Hz=, pitch rises
9/46 of an octave per x step and 1/46 of an octave per y step. All
four args are =f64=, so fractional EDOs work.

* Accretion controls (the five special keys)

Five cells in the bottom-left corner are repurposed from the EDO
grid into a small UI. They form two windows that obscure the EDO
grid beneath them:

#+begin_example
              x=0        x=1        x=2
           +----------+----------+----------+
    y=14   | accrete  |  wipe    |  (EDO)   |
           +----------+----------+----------+
    y=15   | silent   |  emit    |  emit-   |
           |          |          |  toggle  |
           +----------+----------+----------+
                  ^^^accretion 2x2^^^   ^1x1^
#+end_example

| Key            | Kind             | What it does                                      |
|----------------+------------------+---------------------------------------------------|
| =accrete=      | Toggle           | While on, every EDO press adds its pitch to the slot. Toggling on also snapshots whatever's currently held. |
| =wipe=         | Fire             | Empties the slot; any sounding accretion voices ramp to silence. |
| =silent=       | Fire             | Same effect as toggling =emit= off: accretion voices ramp out, =emit= becomes off. |
| =emit=         | Toggle or Nursed | When on, every pitch in the slot sounds at half volume. Mode controlled by =emit-toggle=. |
| =emit-toggle=  | Toggle           | Picks =emit='s mode. On (the default) ⇒ =emit= is a Toggle key; off ⇒ =emit= is Nursed (sounds only while held). |

A pressed EDO key whose pitch is in the slot AND =emit= is on
behaves like the sustain-pedal generalisation: when you release the
finger, the voice doesn't go silent — it ramps from full volume
down to the half-volume accretion level and keeps ringing until
=silent=, =wipe=, or another release event takes it away.

* The monome OSC protocol in one page

All communication is OSC over UDP. The monome (via serialoscd) both
receives commands and sends grid events.

** Discovery

The ``detector'' listens on UDP :12002. Send it:

  =/serialosc/list s <replyHost> i <replyPort>=

It replies, to replyHost:replyPort, with one =/serialosc/device= per
connected device:

  =/serialosc/device s <id> s <type> i <devicePort>=

=devicePort= is where commands for that device go. It is NOT stable:
a new one is picked every time serialoscd notices the device, which
happens on restart or on USB re-enumeration.

** Per-device registration

To receive key events and send LED commands, talk to =devicePort=:

| Send                                | Meaning                               |
|-------------------------------------+---------------------------------------|
| =/sys/host   s "127.0.0.1"=         | Where to forward events back to you.  |
| =/sys/port   i 9000=                | Which UDP port on that host.          |
| =/sys/prefix s "/mygridname"=       | Filter: only commands/events w/ prefix.|

After that, the device sends key events to =127.0.0.1:9000=:

  =/mygridname/grid/key i x i y i s=    (s=1 press, s=0 release)

And accepts LED commands addressed with the same prefix:

  =/mygridname/grid/led/set i x i y i s=
  =/mygridname/grid/led/all i s=

The ``prefix'' is a label you assign to the device. Commands whose
address doesn't begin with the device's current prefix are silently
dropped — if your presses produce no sound and your LEDs don't
change, check the prefix first.

* Known gotcha: ghost /dev/ttyUSBN devices

On one session we observed =systemctl --user status serialoscd=
showing THREE =serialosc-devic= children, one each for
=/dev/ttyUSB{0,1,2}=, all reporting themselves as the same device id
=m0000102= on three different OSC ports (15326, 15997, 16104). Only
the latest tty corresponded to the physically connected grid; the
other two logged =libmonome: error in write: Input/output error=.

Cause: the FTDI USB-serial chip got re-enumerated while serialoscd
was already watching =/dev/ttyUSB0=. The kernel gave the new
enumeration =/dev/ttyUSB1=, then again as =/dev/ttyUSB2=.
serialoscd's detector spawned a fresh =serialosc-device= process for
each new tty but never cleaned up the dead ones.

Symptom inside this project: a client registers via
=/serialosc/list= and gets back one of the ports (say 15326). Key
events never arrive because that port's =serialosc-device= is the
stale one; only the newest port actually reaches the grid.

Fix:

#+begin_src bash
# on the host
systemctl --user restart serialoscd
# unplug the monome, wait ~3 s, replug
#+end_src

After restart =status= should show exactly ONE =serialosc-devic=
child on a single =/dev/ttyUSBN=.

** grid_synth's defense

=grid_synth= watches for =/serialosc/device= messages even after
startup. Any such message with a port different from our current
device port triggers a fresh =register()= to the new port. This
makes the synth survive serialoscd restarts while running, though
it doesn't help with pre-existing stale devices.

* Known issue: latency

Approximately 100 ms between button press and audible sound, even
though the LED response is immediate. Baseline audio buffer size
from PipeWire defaults is the most likely cause (see =grid_synth=
audio stream setup). Being in Docker without RT scheduling may
contribute but is not expected to be the dominant factor.

Mitigations that may help (in order):
- Request a small cpal buffer (=BufferSize::Fixed(256)=).
- Run grid_synth on the host rather than in the container.
- Grant the container =CAP_SYS_NICE= / =--ulimit rtprio=99= so the
  audio thread can be bumped to RT via =audio_thread_priority=.
- Switch from cpal to the JACK client bindings, using PipeWire's
  JACK interface directly.
