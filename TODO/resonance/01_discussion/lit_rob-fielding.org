#+TITLE: Rob Fielding's sympathetic strings, and the prior art behind them
#+DATE: 2026-10-27

* Bottom line
The "Marshall stack" part of Rob's sound is literally amp modeling. His feedback-heavy preset, dgrowl.mq, runs the oud through a Neural Amp Modeler capture of a Marshall JCM800 2203X head before anything else happens. The sympathetic strings are a separate stage: a feed-forward bank of up to 64 two-pole (biquad) resonators, tuned to the current phrase's just-intonation pitches. Each resonator gets the same input added to it ("just add the sound coming in to each string"). Nothing feeds back from the resonators into the input or into each other, so the bank is stable by construction. To get every key resonating with every other key, at pitches that change, Jeff needs a different structure from Rob's: coupled strings (a common bridge or scattering junction, or an FDN with an orthogonal feedback matrix), plus amplifier-feedback simulation (Sullivan 1990, JOS 2008, the Softube patent) for the self-sustaining howl.

** Resonator type
These are modal resonators: one two-pole recursive filter per partial (a "biquad" with only its feedback half). They are not Karplus-Strong delay lines and not comb filters. Each mode is
y[n] = 2 r cos(w) y[n-1] - r^2 y[n-2] + c * drive[n],  w = 2 pi f / sr.
The poles sit at r e^{+-jw}, so the filter is stable whenever r < 1.
** Core loop, src/sympathetics.rs lines 145-213
#+begin_src rust
// src/sympathetics.rs:145-213 (rfielding/maqam @ 59cf449)
pub fn process(&mut self, input: f32) -> f32 {
    let driven_input = (input * self.input_gain).tanh();          // 146: soft-clip the input
    let magnitude = driven_input.abs();
    self.envelope += (magnitude - self.envelope) * 0.0025;        // 148: one-pole envelope
    let onset = (self.envelope - self.previous_envelope).max(0.0);
    ...                                                            // 151-164: adaptive noise gate
    let edge = driven_input - self.previous_input;                // 167: first difference
    self.previous_input = driven_input;
    let sustained_excitation = (driven_input * 0.72 + edge * 3.5) * self.gate;  // 172
    let bridge_strike = onset * 300.0;                            // 173: attack "lights the whole bank"
    ...
    for mode in &mut self.modes {
        mode.modulation_phase = (mode.modulation_phase
            + TAU * mode.modulation_rate / self.sample_rate) % TAU;
        let drift_cents = mode.modulation_phase.sin() * 1.7;      // 187: +-1.7 cent slow drift
        let sounding_frequency = mode.frequency * 2.0f32.powf(drift_cents / 1200.0);
        let frequency_damping = (sounding_frequency / 440.0).max(0.5).sqrt();
        let radius = self.decay.powf(frequency_damping / (self.sample_rate * 0.001)); // 190-192
        let coefficient = 2.0 * radius * (TAU * sounding_frequency / self.sample_rate).cos();
        let drive = if mode.targeted {
            sustained_excitation * (1.0 - radius) + bridge_strike * 0.003   // 195
        } else { 0.0 };                                           // detuned-away strings get no input
        let y = coefficient * mode.y1 - radius * radius * mode.y2 + drive * mode.coupling; // 199
        mode.y2 = mode.y1;
        mode.y1 = y.clamp(-4.0, 4.0);                             // 201: hard state clamp
        sum += mode.y1 * mode.coupling;
    }
    let raw = sum / 8.0 * self.wet;                               // 206: fixed normalization, wet=0.65
    let output = (raw + (raw * 3.0).tanh() * 0.22).tanh();        // 209: "jawari" waveshaper
    self.modes.retain(|mode| mode.targeted || mode.y1.abs().max(mode.y2.abs()) > 0.000_01);
    output
}

** How the input is injected
Every targeted mode receives the same scalar drive, scaled by its own coupling weight (line 199). That makes it a parallel bank with a common input, which matches Rob's "just add the sound coming in to each string". The drive has three parts. The first is the tanh-clipped input times 0.72. The second is 3.5 times its first difference (an "edge", a high-pass emphasis). The third is an onset impulse, the envelope's positive slope times 300 times 0.003, which rings every targeted string on an attack. The first two parts are multiplied by a gate that opens at 3.5 times a learned noise floor, with an attack coefficient of 0.01 and a release of 0.0008 per sample (lines 151-164). The sustained part is also multiplied by (1 - r) (line 195). That normalizes each resonator's peak gain to roughly 1/(2 sin w) whatever its decay. My computation at 48 kHz gives peak gains of 11.9 at 320 Hz, 8.7 at 440 Hz, 3.8 at 1 kHz and 0.9 at 4.5 kHz, so low courses ring loudest.
** Feedback coefficient and damping
`decay` is "retention per millisecond", default 0.999, clamped to 0.9..0.99999 (lines 131-133; the README's "sym decay" entry is at https://github.com/rfielding/maqam/blob/main/README.md around line 245). The per-sample pole radius is r = decay^( sqrt(max(f/440,0.5)) / (sr/1000) ), so higher partials die faster, scaling with sqrt(f). My computed T60 at 48 kHz with decay 0.999 is 8.1 s at 320 Hz, 6.9 s at 440 Hz, 4.6 s at 1 kHz and 2.2 s at 4.5 kHz. With decay 0.995, the mic setting in some presets, it is 1.6 s at 320 Hz and 0.43 s at 4.5 kHz.
** How pitches are set
The pitches come from the score, not from pitch tracking. set_targets (lines 42-56) takes the current phrase's exact just-intonation frequencies and adds the tonic times 4/3 and times 3/2 ("Taraf strings prominently reinforce the tonic, fourth, and fifth"). set_weighted_targets (lines 58-129) folds each pitch into the 320-640 Hz octave. It then adds harmonics 1, 2, 3, 4, 5, 6, 8, 10 and 12, with weights from 1.0 down to 0.24, keeps only partials below 4.5 kHz, and merges any within 8 cents. The list is sorted and truncated to 64 modes. On a phrase change, existing modes within 8 cents are retuned in place. Others are marked untargeted, so they get no input and ring out, and they are deleted once below 1e-5. src/audio.rs lines 127-196 add "sym harmony root 0.5 third 0.25 ...", which spreads target weight across just-intonation intervals normalized to a total of 1. README lines 138-182 (https://github.com/rfielding/maqam/blob/main/README.md) describe this as a "score-aware effect": "Live audio supplies energy, while the score determines which virtual strings can accept that energy."
** Number of resonators and crosstalk
There are at most 64 modes per bank (line 104). src/audio.rs lines 104-124 build four independent banks, one each for the mic, the kanun synth voice, the bass and the drums. Each bank is fed only from its own source (process_sym_partition, lines 267-278), and their outputs are summed (lines 183-196). There is no crosstalk. No mode's output feeds any other mode or the input, and the bank output never returns to the input stage. The only "feedback" is each two-pole filter's own recursion. The bank is driven at src/audio.rs lines 1034-1041 with live_input, which by then has already passed through NAM and the cabinet IR (lines 915-927). So the strings are excited by the distorted, amp-modeled signal.
** Runaway protection
Rob's code has several layers. Stability itself is guaranteed because r < 1: the decay clamp of 0.99999 per ms keeps r below 1. On top of that come a tanh on the input, a hard clamp of each state at +-4 (line 201), a fixed divide-by-8 instead of divide-by-N ("so adding the next phrase's strings never turns down a chord that is already ringing", lines 204-206), and a final tanh waveshaper. Further down the chain, src/analog.rs lines 1-6 soft-clip the master with tanh(0.85x + 0.2(0.85x)^3), and the output is clamped to +-1 (src/audio.rs around line 1100).
** Sample rate and language
The sample rate is whatever the default cpal output device reports (src/audio.rs line 400, `let sr = defcfg.sample_rate().0 as f64`). The unit tests assume 48 kHz. The language is Rust (2021 edition).

** Rob's older code: AlephOne/Cantor (iOS, 2012-13), a pitch-tuned feedback comb
https://github.com/rfielding/AlephOne, file AlephOne/RawEngine.m (last commit 5aa365d, 2013-01-04, at 44.1 kHz per line 37), contains a "reverb" that is really a multi-tap feedback comb tuned to a pitch. * 2. Prior-art family
** Karplus-Strong (1983)
K. Karplus and A. Strong, "Digital Synthesis of Plucked-String and Drum Timbres", Computer Music Journal 7(2):43-55, 1983 (https://users.soe.ucsc.edu/~karplus/digitar.html, https://en.wikipedia.org/wiki/Karplus%E2%80%93Strong_string_synthesis). A delay line of length P is filled with noise, and each pass averages two samples: y[n] = x[n] + 0.5(y[n-P] + y[n-P-1]). It sounds like a plucked string or harpsichord, bright at the attack and then mellowing. It is stable because the two-point average has magnitude cos(wT/2), which is at most 1 at every frequency. When the delay is excited by live input instead of noise, it becomes a comb resonator, the building block of most sympathetic-string effects.
** Jaffe and Smith extensions (1983)
D. A. Jaffe and J. O. Smith, "Extensions of the Karplus-Strong Plucked-String Algorithm", Computer Music Journal 7(2), 1983, summarized at https://ccrma.stanford.edu/~jos/pasp/Extended_Karplus_Strong_Algorithm.html. The extensions add pick-direction and pick-position filters, a damping filter H_d, a stiffness allpass, a tuning allpass for fractional delay, and a dynamic-level lowpass. The stated stability condition is |H_d(e^{jwT})| <= 1. That page does not mention sympathetic strings. A UMD lecture summary credits Jaffe and Smith with "sympathetic strings" as parallel string instances that "bleed into each other" (https://www.cs.umd.edu/class/fall2019/cmsc828X/LEC/plucksim.pdf). The original paper's wording on this is UNVERIFIED.
** Sullivan (1990): distortion and amplifier feedback in Karplus-Strong
C. R. Sullivan, "Extending the Karplus-Strong algorithm to synthesize electric guitar timbres with distortion and feedback", Computer Music Journal 14(3):26-37, 1990 (citation via https://cycling74.com/forums/creating-feedback-like-a-guitar-amp-might and https://ccrma.stanford.edu/realsimple/faust_strings/Amplifier_Feedback.html). JOS summarizes the model: "The sum of all vibrating strings was passed through the cubic nonlinearity, multiplied by a feedback gain, delayed, and summed into the strings" (https://ccrma.stanford.edu/realsimple/faust_strings/Amplifier_Feedback.html). This is the canonical "Marshall-stack feedback" model, and it is all-to-all coupling: every string hears the distorted sum of all strings. RTcmix's STRUM2 reportedly implements it (cycling74 link above; UNVERIFIED in source).
** Julius O. Smith: coupled strings, bridge scattering, virtual electric guitar
PASP "Two Ideal Strings Coupled at a Bridge" (https://ccrma.stanford.edu/~jos/pasp/Two_Ideal_Strings_Coupled.html) covers N strings on one bridge. All string endpoints share the bridge velocity, and the forces sum. The result is
V_b(s) = H_b(s) * sum_i R_i V_i^+(s),  H_b(s) = 2 / (R_b(s) + sum_i R_i),  v_i^- = v_b - v_i^+.
R_i is each string's wave impedance and R_b(s) is the bridge's driving-point impedance, which is positive real if the bridge is passive. JOS calls this a "one-filter scattering termination": the coupling costs one shared filter, not N^2 transfer functions. Any string's energy reaches all the others, and the coupling automatically weakens as more strings are attached, because sum R_i grows. The REALSIMPLE Faust version (https://ccrma.stanford.edu/realsimple/faust_strings/Coupled_Strings_Faust.html) uses H_b = 0.5 (R_b = 2R) and per-string loop gains of 0.999 and 0.995. The simplified one-liner is `stringloop = (+ <: d2,d1 : + : *(0.5)) ~ *(g);`. The LAC2008 paper "Virtual Electric Guitars and Effects Using Faust and Octave" (https://ccrma.stanford.edu/~jos/pdf/LAC2008-jos.pdf) combines the strings with a cubic soft clipper, f(x) = x - x^3/3 on |x| < 1 and +-2/3 outside (https://ccrma.stanford.edu/realsimple/faust_strings/Cubic_Nonlinear_Distortion.html), and with amplifier feedback, for "convincing synthesis of howling overdriven electric guitars" (https://ccrma.stanford.edu/realsimple/faust_strings/Distortion_Amplifier_Feedback.html). The PASP background on piano "aftersound" cites Weinreich (https://ccrma.stanford.edu/~jos/pasp/Coupled_Strings.html).
** Weinreich (1977): coupled piano strings
G. Weinreich, "Coupled piano strings", JASA 62(6), 1977. The volume and issue are from memory (UNVERIFIED); discussion is at https://www.speech.kth.se/music/5_lectures/weinreic/weinreic.html. Unison strings slightly mistuned and coupled through a yielding bridge form normal modes, one fast-decaying and one slow-decaying. The result is the two-stage decay and beating of piano tone. This is the physics reason mutual coupling sounds alive: coupled modes split and trade energy.
** Karjalainen, Välimäki and Tolonen (1998), and the Helsinki string models
"Plucked-String Models: From the Karplus-Strong Algorithm to Digital Waveguides and Beyond", Computer Music Journal 22(3), 1998. The bibliographic details come from secondary citations, e.g. https://muse.jhu.edu/article/7837/pdf, and the paper's sympathetic-coupling content is UNVERIFIED. Laurson, Erkut, Välimäki and Kuuskankare's guitar model (same muse.jhu.edu excerpt) includes "sympathetic couplings between the strings" around per-string loop filters. The broad review is Välimäki, Pakarinen, Erkut and Karjalainen, "Discrete-time modelling of musical instruments", Rep. Prog. Phys. 69:1-78, 2006 (https://www.ece.uvic.ca/~bctill/papers/numacoust/V%c3%a4lim%c3%a4ki_etal_2006.pdf).
** Piano sympathetic resonance and sustain pedal (Bank, Zambon, Lehtonen, Fontana)
S. Zambon, H.-M. Lehtonen and B. Bank, "Simulation of piano sustain-pedal effect by parallel second-order filters", DAFx-08 (https://dafx.de/paper-archive/details/5mJ31JDQWZTHNiqjmf19mQ). With the dampers lifted, all strings resonate. They model that with a bank of parallel second-order filters (the same resonator type as Rob's) fitted to measured soundboard and string-register responses, "taking into account the differences in coupling between the various strings". B. Bank, S. Zambon and F. Fontana, "A Modal-Based Real-Time Piano Synthesizer", IEEE TASLP 18(4):809-821, 2010 (https://iris.univr.it/handle/11562/342223, sound examples at https://home.mit.bme.hu/~bank/publist/taslp-piano/index.html), models full strings modally and the soundboard with parallel second-order filters. Whether that 2010 paper includes inter-string sympathetic coupling is UNVERIFIED (the abstract doesn't say). The precursor analysis is Lehtonen, Penttinen, Rauhala and Välimäki, "Analysis and modeling of piano sustain-pedal effects", JASA 2007, cited at https://dafx.de/paper-archive/details/5mJ31JDQWZTHNiqjmf19mQ (details UNVERIFIED). This family is the closest academic analogue to Rob's bank: a fixed set of tuned two-pole resonators excited by the instrument's output.
** Mutable Instruments Rings: "sympathetic strings" mode (open source)
Code is at https://github.com/pichenettes/eurorack/tree/master/rings/dsp (read at f4cfa76). It runs at 48 kHz (dsp.h:39), with 8 strings shared across 1, 2 or 4 voices (part.h:63-64). Each string is a Karplus-Strong/waveguide loop. The key line is string.cc:191, `s += *in;`: the input is literally added into each string's delay loop, then damped by an FIR and an SVF lowpass and written back (string.cc:188-196). The per-period loop gain is damping_coefficient = 2^(-10 * delay/rt60), which is exactly -60 dB per rt60 samples (string.cc:104-106). It crossfades to exactly 1.0 ("infinite decay") at damping >= 0.95 (string.cc:115-121). Coupling is strictly one-way: string 0 is excited, and its output times 0.2/num_strings is the input of all the other strings (part.cc:427-455). Sympathetic strings never feed back to string 0 or to each other, so stability reduces to each string being stable. String pitches are the played note plus intervals set by the Structure knob (octaves, fifths, and slight detunings of 0.007 to 0.017 semitones, part.cc:242-290), or a quantized chord table. A peak limiter with a 0.05/0.00002 attack/release slope and SoftLimit sits on the output only (limiter.h:50-71). The manual calls the mode "Sympathetic strings, modelled by a network of comb filters" (https://cdn.softube.com/user-manuals/mutable-instruments-rings), and reviewers compare it to sitar and sarod (https://www.soundonsound.com/reviews/mutable-instruments-rings). Rings' other "modal" model is a bank of up to 64 SVF bandpasses (resonator.h:42), the same idea as Rob's biquads.

** Sitar and tanpura models

* 3. Is "amp modeling" the right genre?
It is half right. For Rob's actual timbre it is literally right: the Marshall character is a NAM capture of a JCM800 (dgrowl.mq; https://www.tone3000.com/tones/41179). Amp modeling (NAM, wave digital filters, state-space tube models such as Yeh and Smith, DAFx-08, https://dafx.de/paper-archive/details/gZvqz8Bk39w9LqNNr1SDlg) explains the distortion, but not the sustain-and-bloom behavior. The behavior Jeff wants, with every key resonating every other key and notes blooming into howl, belongs to three other genres.
** Guitar or acoustic feedback simulation
The papers are Sullivan 1990, JOS LAC2008 (https://ccrma.stanford.edu/~jos/pdf/LAC2008-jos.pdf) and Softube's patent US7572972 (Fredrik Gustafsson, filed 2005, https://patents.google.com/patent/US7572972). The patent's loop is guitar input, plus feedback, into a static nonlinear amplifier f(e) = arctan(e), into a "room" a z^-T (the volume control stands in for the guitar-to-amp distance), into a string band-pass G(z) on the tracked fundamental or chosen harmonics, and back. It argues from describing-function theory that the static nonlinearity turns linear runaway into a stable limit cycle, i.e. sustained feedback. The product is Softube Acoustic Feedback (https://softube.com/af; the manual says to put it before the amp sim, https://softube.com/user-manuals/acoustic-feedback). The hardware analogues are the Sustainiac and Fernandes sustainers and the EBow: a pickup drives an electromagnetic driver in phase with the string (e.g. US5932827, https://image-ppubs.uspto.gov/dirsearch-public/print/downloadPdf/5932827, and US5200569, https://patents.google.com/patent/US5200569).

* 4. Keeping a bank of mutually coupled resonators stable
** Rule 0: stable parts, feed-forward coupling
If coupling is feed-forward, as in Rob (one input to all resonators) or Rings (string 0 to the rest, part.cc:448-455), the system is stable whenever each resonator is: r < 1 for a biquad, |loop filter| <= 1 for a delay loop (https://ccrma.stanford.edu/~jos/pasp/Extended_Karplus_Strong_Algorithm.html). No coupling analysis is needed. The cost is that there is no true mutual resonance: key A never re-excites key B, which would then re-excite A.
** Rule 1: loop gain below 1 under all-to-all coupling
Suppose each of N resonators adds c times every other resonator's output to its input. A shared frequency then sees a loop gain of about c (N-1) G_peak, where G_peak is the resonator's peak gain at that frequency. The structure is stable only if this is below 1. This is my derivation. For Rob-style (1-r)-normalized biquads, G_peak is about 1/(2 sin w): 8.7 at 440 Hz and 11.9 at 320 Hz at 48 kHz (computed above). With 10 keys sounding, c must be below about 1/(9 x 8.7), roughly 0.013 at 440 Hz. Unisons and octaves between keys make the coupling strongest, because their peaks coincide. The general sufficient condition is that the feedback matrix shrinks the L2 norm: ||A||_2 < 1 (https://ccrma.stanford.edu/~jos/pasp/FDN_Stability.html).
** Rule 2: energy-preserving coupling plus separate, explicit loss
This is the FDN recipe: write the coupling as A = Gamma Q, with Q orthogonal or unitary and Gamma = diag(g_i), |g_i| < 1 (https://ccrma.stanford.edu/~jos/pasp/FDN_Stability.html). Q only moves energy between strings and never creates it, while Gamma sets each string's decay. For per-string T60 with delay M_i samples, use g_i = 10^(-3 M_i / (T60 * sr)); this is standard and matches Rings' 2^(-10 delay/rt60) in string.cc:105. An O(N) all-to-all Q is the Householder matrix Q = I - (2/N) 1 1^T (https://ccrma.stanford.edu/~jos/reverb/JotReverb_STK.html). That is literally "each string gets everyone's sum, minus twice the average": x_i <- x_i - (2/N) sum_j x_j. It is orthogonal for any N, so Jeff can resize it as keys come and go. Rocchesso and Smith show that an orthogonal-matrix FDN is a normalized waveguide network with one scattering junction (IEEE TSAP 5(1):51-63, 1997, https://www.di.univr.it/documenti/ArticoloRivista/allegato/allegato574545.pdf). Schlecht and Habets prove losslessness holds for any delay lengths when Q is unitary, or diagonally similar to unitary (IEEE TSP 65(6):1554-1564, 2017, https://arxiv.org/pdf/1606.07729). That matters for Jeff because the pitches, i.e. the delay lengths, can change without breaking stability. One caveat: continuously modulating delays or matrices can inject energy, so smooth retuning slowly. That caveat is from Schlecht's time-varying FDN work and is UNVERIFIED here. A frequency-dependent generalization is "Scattering in Feedback Delay Networks" (Schlecht and Habets, IEEE/ACM TASLP 2020, https://cris.fau.de/converis/portal/publication/240995574?lang=de_DE).
** Rule 3: physical coupling through a passive bridge
Couple through a common bridge, as in JOS's "one-filter scattering termination" (https://ccrma.stanford.edu/~jos/pasp/Two_Ideal_Strings_Coupled.html). Each string's incoming wave v_i^+ is read from its delay line. Compute v_b = H_b * sum_i R_i v_i^+ with H_b = 2/(R_b + sum_i R_i), write back v_i^- = v_b - v_i^+, and apply each string's own loop filter. If R_b(s) is positive real (passive), the junction cannot add energy. Adding keys raises sum R_i and automatically lowers the per-string coupling, which is the principled form of Rob's ad-hoc "/8". A lossy, i.e. resistive, R_b drains every attached string, so it doubles as the global damping control. The Faust reference implementation is at https://ccrma.stanford.edu/realsimple/faust_strings/Coupled_Strings_Faust.html. Wave digital filters give the same passivity guarantee for arbitrary networks (Fettweis, "Wave digital filters: theory and practice", Proc. IEEE 74(2), 1986; citation from memory, UNVERIFIED).
** Rule 4: if you want Marshall-style howl, let the gain exceed 1 and saturate it in the loop
For the self-sustaining howl, deliberately let the small-signal loop gain exceed 1 on a separate "amp" path: sum of strings, then a nonlinearity, then gain g_fb, then delay T, then back into the strings (Sullivan; https://ccrma.stanford.edu/realsimple/faust_strings/Amplifier_Feedback.html). Use a bounded, memoryless nonlinearity whose slope falls with amplitude: the cubic x - x^3/3 clipped at +-2/3 (https://ccrma.stanford.edu/realsimple/faust_strings/Cubic_Nonlinear_Distortion.html), or arctan (US7572972). The oscillation then settles where the nonlinearity's describing-function gain times the linear loop gain equals 1. That gives a bounded limit cycle rather than blow-up, and it lands at whichever string partial has the highest linear loop gain. The patent selects harmonics with a band-pass and gates the loop on input energy (https://patents.google.com/patent/US7572972). Distance-to-amp maps to g_fb and T, which set which partial "catches", as on a real stage. Keep this path separate from the lossless coupling network so the two concerns stay independent.
** Rule 5: belt-and-braces outside the loop
Add a DC blocker inside each loop when a nonlinearity is present, because an asymmetric clipper creates DC (https://ccrma.stanford.edu/realsimple/faust_strings/Cubic_Nonlinear_Distortion.html). Clamp the state (Rob's +-4 at sympathetics.rs:201). Put a peak limiter on the output only (Rings limiter.h:50-71). These guard against numerical surprises but do not replace Rules 1-3. A limiter outside the loop cannot stop internal growth. A clamp inside the loop can, but it adds distortion.
