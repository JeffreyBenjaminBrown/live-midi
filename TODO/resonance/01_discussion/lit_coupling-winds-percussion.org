* Verdict in one paragraph
Jeff is mostly right. Every wind or brass model I found is tuned around one instrument's register, and real wind ranges come from a family of instruments (piccolo down to contrabass tuba), not from one model stretched. The blown models are also self-oscillators, so coupling them gives frequency locking and pitch pulling, not sympathetic ringing. Struck/modal models (bars, plates, membranes) are linear and passive, so they couple safely, but their cost grows as pitch falls. For the "every key talks to every key" bank, the clean answer is Smith's shared-bridge junction. It costs O(N), stays passive for any N and any pitches, and renormalises itself as notes come and go. The "Marshall stack" sound needs a separate active path: sum of all notes, then gain, then a saturator, then a delay, then back into every note. That path is bounded by the saturator and is the one place where a buffer of latency is harmless. I checked these claims with a toy Rust simulation (section "My own toy test").

* A. Wind and brass models: range and self-oscillation
** What "self-oscillating" means here
In every blown model below, a steady (DC) breath or lip pressure goes into a nonlinearity at the end of a resonator. The loop then oscillates on its own; no periodic input is needed. Smith describes the clarinet reed as "a signal- and embouchure-dependent nonlinear reflection coefficient terminating the bore". The mouth pressure biases the reed into a "negative-resistance" region, and that is what sustains the oscillation (https://ccrma.stanford.edu/~jos/pasp/View_Single_Reed_Oscillation.html, https://ccrma.stanford.edu/~jos/pasp/Digital_Waveguide_Single_Reed_Implementation.html). So coupled blown notes behave like coupled oscillators: they lock, pull and beat. They do not behave like passive resonators that only ring.
** STK Clarinet (Cook and Scavone)
The model is one delay line plus a one-zero loss filter plus a reed table, and the delay is set to half the period. That makes it a closed-open cylinder with odd harmonics only (source read from https://raw.githubusercontent.com/thestk/stk/master/src/Clarinet.cpp; docs at https://ccrma.stanford.edu/software/stk/classstk_1_1Clarinet.html):
#+begin_src c++
// Clarinet::setFrequency
delay = (fs / frequency) * 0.5 - filter_.phaseDelay(frequency) - 1.0;
// Clarinet::tick
pressureDiff = -0.95 * filter_.tick(delayLine_.lastOut()) - breathPressure;
out = delayLine_.tick(breathPressure + pressureDiff * reedTable_.tick(pressureDiff));
// ReedTable: r = offset + slope*x, clipped to [-1,1]; Clarinet uses offset 0.7, slope -0.3
#+end_src
Range: the constructor's lowestFrequency (default 8 Hz) only sizes the buffer. The loss filter is a fixed one-zero filter whose decay is set per round trip, so decay per second grows with pitch: high notes are short and thin, low notes are long and dark. The delay line is linear-interpolating (DelayL), which damps and detunes short delays, so the top octaves suffer (https://ccrma.stanford.edu/software/stk/Clarinet_8h_source.html). There are no register holes, so the model never changes register the way a real clarinet's 12th key does. The STK BlowHole class adds one tone hole and one register vent (https://raw.githubusercontent.com/thestk/stk/master/src/BlowHole.cpp). It is self-oscillating.
** STK Saxofony
This is the "blowed string" model. A string-like waveguide with one rigid and one lossy end is excited at a variable point by a reed table. A position at mid-string sounds like a clarinet; positions nearer the "bridge" sound more like a saxophone. It fakes a conical bore (Scavone 2002) (https://ccrma.stanford.edu/software/stk/classstk_1_1Saxofony.html, https://raw.githubusercontent.com/thestk/stk/master/include/Saxofony.h). The delay is one full period. It is self-oscillating, and range is limited the same way as the Clarinet.
** STK Flute (jet)
The model has a bore delay, plus a jet delay of jetRatio times the bore delay (default 0.32), plus the jet nonlinearity y = clip(x*(x^2 - 1), -1, 1), plus end and jet reflections of 0.5 (https://raw.githubusercontent.com/thestk/stk/master/src/Flute.cpp, https://raw.githubusercontent.com/thestk/stk/master/include/JetTable.h). Changing the jet/bore ratio makes the model jump register (overblow), which is how a real flute covers about three octaves. A flute keeps that ratio within a narrow band. Sweeping the bore delay over seven octaves at a fixed ratio is not physical: low notes become breathy and unstable, and the top notes run out of samples. That last point is my inference, not tested (UNVERIFIED as a listening claim). It is self-oscillating.
** STK BlowBotl
Here the bore is replaced by a single two-pole resonator, a Helmholtz bottle with fixed pole radius 0.999. Noise is modulated by breath and fed in through the jet table (https://raw.githubusercontent.com/thestk/stk/master/src/BlowBotl.cpp). Because it uses no delay line, it can take any pitch cheaply. With only one mode it sounds like a bottle at every pitch, so the timbre is consistent but plain. It is self-oscillating.
** STK Brass (Cook's TBone/HosePlayer)
The model is a delay line plus a lip filter (a biquad resonance at the note frequency, radius 0.997). The filter's output is squared and clipped to 1 to give lip opening area, and then mixes mouth and bore pressure (https://raw.githubusercontent.com/thestk/stk/master/include/Brass.h). The bore is deliberately tuned one octave low (delay = 2*fs/f + 3; the code comment says "play a harmonic"), so the lips select the second bore resonance (https://raw.githubusercontent.com/thestk/stk/master/src/Brass.cpp). In this model, as on a real horn, pitch is a negotiation between the lip resonance and the bore's harmonic series. Mistune the two and the note jumps partials or chokes. That is great for expression and bad for an all-to-all coupling bank. Smith's brass chapter says shock-wave nonlinearity matters at loud levels and is expensive to simulate (https://ccrma.stanford.edu/~jos/pasp/Brasses.html).
** Faust physmodels.lib (Michon and Smith)
These are the same mouthpiece/reed/jet + bore + bell blocks, built from bidirectional waveguide sections (https://faustlibraries.grame.fr/libs/physmodels, https://hal.archives-ouvertes.fr/hal-02158706). The older Faust-STK ports describe all the winds as sharing one structure: an envelope-driven breath pressure into a nonlinear exciter into waveguides (https://ccrma.stanford.edu/~rmichon/publications/doc/DAFx11-Faust-STK.pdf). Range limits are the same as STK. Not verified per model (UNVERIFIED).
** Mutable Instruments Elements: blow exciter and Tube
The "blow" generator is pitched granular noise with its own envelope, fed into the 64-mode modal resonator (https://modulargrid.net/e/modules/view/4606, https://perfectcircuit.com/mutable-instruments-elements.html). Separately, elements/dsp/tube.cc is a tiny clarinet-like reed waveguide, essentially the STK reed with a hard limit (source from https://raw.githubusercontent.com/pichenettes/eurorack/master/elements/dsp/tube.cc):
#+begin_src c++
float delay = 1.0f / frequency;
while (delay >= float(kTubeDelaySize)) delay *= 0.5f;   // kTubeDelaySize = 2048: octave-folds very low notes
float pressure_delta = -0.95f * (in * envelope + zero_state_) - breath;
float reed = pressure_delta * -0.2f + 0.8f;
float out = pressure_delta * reed + breath;
CONSTRAIN(out, -5.0f, 5.0f);                             // hard clip inside the loop keeps it bounded
#+end_src
Below the 2048-sample limit, pitch quietly jumps up an octave. Elements' bowed modes are 8 banded waveguides (a band-pass filter plus a delay per mode) driven by a bow table, so they are self-oscillating as well (https://raw.githubusercontent.com/pichenettes/eurorack/master/elements/dsp/resonator.cc).
** Yamaha VL1 / VL70-m
The VL1 (1994) is duophonic; the VL70-m is a monophonic, cheaper sibling. Sound On Sound says polyphony was limited by DSP cost (https://www.soundonsound.com/reviews/yamaha-vl1, https://www.soundonsound.com/reviews/yamaha-vl70m-0, https://www.vintagesynth.com/yamaha/VL-70m). Each patch models one instrument, including its "driver" (reed, lip or bow) and its bore. I could not verify the per-patch pitch ranges, or confirm that the drivers self-oscillate (UNVERIFIED, though that is how S/VA is generally described).
** AAS Tassman and Chromaphone
Tassman is a modular physical-modelling environment with about 14 resonators and 5 drivers. It was reportedly discontinued around 2019, but only a forum source says so (https://www.soundonsound.com/reviews/applied-acoustic-systems-tassman-v12, https://www.kvraudio.com/forum/viewtopic.php?p=7401285). Chromaphone is two resonators (string, beam/bar, marimba, plate, drumhead/membrane, tube, manual) excited by a mallet and a noise source, and the two can be coupled bidirectionally (https://www.soundonsound.com/reviews/aas-chromaphone, https://rekkerd.org/review-applied-acoustics-systems-chromaphone/). Its "blown" sounds are a noise source into a tube, which is not self-oscillating. I found no published pitch range (UNVERIFIED).
** Brass range and the piccolo trumpet
The piccolo trumpet is the instrument Jeff forgot. It is pitched one octave above the B-flat trumpet, and its fourth valve extends the low range by a fourth (https://en.wikipedia.org/wiki/Piccolo_trumpet). Tubas reach about E1, contrabass tubas reach Bb0, and lower notes are unstable pedal tones (https://www.good-music-guide.com/community/index.php?msg=141463, https://en.wikipedia.org/wiki/Range_(music)). So brass does span the piano's range, but only as a family of bores and mouthpieces, never as one model.
** Why winds fall short of strings over a 7-octave range
This is a synthesis of the sources above; I did not find it stated as one claim. A string's timbre scales almost uniformly with length: pluck position, loss filter and stiffness all scale gently. A wind model has three parts that do not scale together. The exciter has its own resonance (reed or lip mass, or the jet travel time), and its ratio to the bore resonance decides whether the note speaks, squeaks or jumps register (STK Brass lip filter; Flute jetRatio). Fixed per-round-trip loss filters make decay and brightness depend strongly on pitch. And the register-selection hardware (tone holes, register vents, valves) is missing or fixed. So one blown model is good over about 2 to 3 octaves, and a piano-wide wind needs a family of patches split by register.

* B. Percussion and modal models
** Mode ratios are known and inharmonic
The ideal free-free bar has modes at 1 : 2.756 : 5.404 : 8.933 (https://www.pas.rochester.edu/~sybenzvi/courses/phy103/2016f/phy103_bars_and_bells.pdf, https://csound.com/manual/MiscModalFreq.html). Marimba bars are arched underneath to retune the partials to about 1 : 4 : 9.2 (https://ccrma.stanford.edu/courses/150-spring-2003/percussion.html). The ideal circular membrane follows the Bessel zeros, giving 1 : 1.59 : 2.14 : 2.30 ... (https://en.wikipedia.org/wiki/Vibration_of_a_circular_membrane). That is why a bar or drum bank couples very differently from strings: coincident partials between notes are rare unless the ratios are deliberately harmonic.
** Elements and Rings modal resonators
Rings and Elements use 64 band-pass state-variable filters, one per mode. Partial k sits at k*f0 times a stretch factor (stiffness from the "geometry"/"structure" knob), Q is scaled per mode, and modes at or above 0.49*fs are dropped (https://raw.githubusercontent.com/pichenettes/eurorack/master/rings/dsp/resonator.cc, https://raw.githubusercontent.com/pichenettes/eurorack/master/elements/dsp/resonator.cc). The consequence for range: the 64-mode cap means a 30 Hz note has partials only up to about 2 kHz, so it sounds dull. High notes run out of modes below Nyquist and become nearly sinusoidal. Cost per note is proportional to the number of modes, roughly Nyquist/f0 for a bright tone, so low notes are expensive, the reverse of a waveguide, which costs one delay line at any pitch.
** Rings' "sympathetic strings" mode is one-way, not all-to-all
String 0 is the excited string. Its output, scaled by 0.2/num_strings, is the only input to the other strings, and they never feed back (https://raw.githubusercontent.com/pichenettes/eurorack/master/rings/dsp/part.cc):
#+begin_src c++
if (string == 0) {
  float gain = 0.2f / static_cast<float>(num_strings);
  for (size_t i = 0; i < size; ++i) sympathetic_resonator_input_[i] = gain * (out_buffer_[i] - aux_buffer_[i]);
}
#+end_src
Because the coupling is one-way, it is unconditionally stable, and it is block-based without any problem: a feed-forward path cannot be destabilised by delay.
** Bilbao (NESS) plates, membranes, gongs and Modalys
Bilbao's finite-difference plates and membranes, including the nonlinear von Karman gong, are energy-conserving and were made real-time only recently, with SIMD and invariant energy quadratization (https://dafx.de/paper-archive/details/_HhxQRl-yal5hunEZ5gckQ, https://ccrma.stanford.edu/events/real-time-sound-synthesis-2-d-plates-using-fdtd-methods). They are too expensive for dozens of simultaneous notes. Ducceschi, Touze and Bilbao note that the modal approach suits linear and moderately nonlinear plates and allows per-mode damping (https://perso.ensta-paris.fr/~touze/PDF/ducceschi_smac2013.pdf). Modalys (IRCAM) is modal synthesis built from objects (strings, plates, tubes, membranes) joined by "connections", with real-time use in Max (https://support.ircam.fr/docs/Modalys/3.8.0/index.html).
** Modal resonators as the "strings" of a sympathetic bank
They are good candidates, with caveats. Each mode is a stable LTI two-pole filter (stable whenever the pole radius is below 1) with arbitrary frequency, so microtonal and inharmonic tunings cost nothing extra. The Mathews-Smith complex-multiply ("phasor") resonator lets frequency and damping change on the fly with no output discontinuities; they ran 200 at once on an 800 MHz PC in 2003 (https://ccrma.stanford.edu/~jos/smac03maxjos, https://ccrma.stanford.edu/~jos/smac03maxjos/High_Q_Filter_Difference.html). That is exactly the "pitch set per note on the fly" case.
#+begin_src rust
// Mathews-Smith style mode: z <- z * r*e^{j w} + x ; output Im(z). Retuning w or r leaves |z| intact.
let (c, s) = (r * w.cos(), r * w.sin());
let (re, im) = (re * c - im * s + x, re * s + im * c);
#+end_src
The caveats: low notes need many modes, and two-way coupling of modal objects must still be passive. Bank and Karjalainen build passive admittance matrices as sums of positive-real second-order sections times positive semidefinite matrices, then convert them to reflectances for waveguides (https://dafx.de/paper-archive/details/KhIp4wXYNNsFzCbLHElaPA, https://www.dsprelated.com/freebooks/pasp/Matrix_Bridge_Impedance.html). A practical split: waveguide strings for the low and middle range, where they are cheap and harmonic, and modal resonators for the top octaves, or wherever inharmonic bar or bell colours are wanted.

* C. Coupling N resonators all-to-all, with N changing at runtime
** (a) Feedback delay networks and losslessness
The FDN state is s_i(n + m_i) = sum_j a_ij s_j(n) + b_i x(n), with output y(n) = sum_i c_i s_i(n) + d x(n). Its transfer function is H(z) = c^T [D_m(z^-1) - A]^-1 b + d, where D_m = diag(z^-m_i). Schlecht and Habets prove that the network is lossless for every choice of delays exactly when each irreducible block of A is diagonally similar to a unitary matrix. Unitary/orthogonal and triangular-with-unimodular-diagonal A both qualify (https://ar5iv.labs.arxiv.org/html/1606.07729, IEEE TSP 65(6):1554-1564, 2017). Jot and Chaigne (AES 90th, 1991, preprint 3030) add a damping filter to each line so all lines decay at the same frequency-dependent rate (https://aes2.org/publications/elibrary-page/?id=5663, https://valhalladsp.com/2021/09/22/getting-started-with-reverb-design-part-2-the-foundations/). Smith shows that an FDN is a digital waveguide network with every branch meeting at one scattering junction. For N branches with admittances Gamma_i, the junction is a negative Householder reflection, and it is lossless iff A^H Gamma A = Gamma (https://www.dsprelated.com/freebooks/pasp/FDNs_Digital_Waveguide_Networks_I.html). Scattering delay networks (De Sena et al. 2015) are fully connected waveguide networks whose lossless matrices have all eigenvalues on the unit circle and a full set of eigenvectors; stability follows from that physical reading (https://arxiv.org/pdf/1502.05751). Schlecht and Habets (JASA 138(3):1389, 2015) also treat time-varying feedback matrices (https://cris.fau.de/publications/212195437).
** (b) Coupled piano strings and the shared bridge
Weinreich (JASA 1977) explains the piano's two-stage decay. In-phase unison strings lose energy fast through the bridge ("prompt sound", about 8 dB/s in his example). The antiphase mode barely moves the bridge and decays more than four times slower ("aftersound"). Slight mistuning plus bridge admittance sets the mix, and simply summing detuned strings gives beating but no true two-stage decay (https://www.speech.kth.se/music/5_lectures/weinreic/weinreic.html, https://www.dsprelated.com/freebooks/pasp/Coupled_Strings.html). Smith's model of strings on a common bridge is the formula to build on (https://ccrma.stanford.edu/~jos/pasp/Two_Ideal_Strings_Coupled.html, https://ccrma.stanford.edu/~jos/pasp/Loaded_Waveguide_Junctions.html):
#+begin_example
series junction (common velocity, forces add), N strings, impedances R_i, bridge impedance R_b(s):
  V_b(s)    = H_b(s) * sum_i R_i V_i^+(s)          H_b(s) = 2 / (R_b(s) + sum_i R_i)
  V_i^-(s)  = V_b(s) - V_i^+(s)
identical strings (R_i = R), r = R_b/R:
  v_b = alpha * sum_i v_i^+        alpha = 2 / (N + r)
  scattering matrix S = alpha * 1 1^T - I
  r = 0       -> S = -(I - (2/N) 1 1^T) = negative Householder: orthogonal, lossless
  r > 0 real  -> eigenvalue on the all-ones (in-phase) mode is (r - N)/(r + N), |.| < 1: passive
  r >> N      -> alpha ~ 2/r: fixed per-pair coupling, independent of N (the real piano regime,
                 heavy soundboard; UNVERIFIED as a quantitative claim about pianos)
  R_b(s) positive real (passive bridge filter) -> still stable; Smith warns that an active
                 bridge model "can make the whole guitar model unstable"
#+end_example
The cost is O(N): one sum, one multiply, and one subtract per string. This is Jot's remark that the Householder matrix equals "N parallel feedback comb filters with one new feedback path" (https://ccrma.stanford.edu/~jos/pasp/Householder_Feedback_Matrix.html). Bank, Zambon and Fontana's real-time modal piano (IEEE TASLP 18(4), 2010) and Zambon, Lehtonen and Bank's sustain-pedal model (parallel second-order filters fitted to soundboard and string-register responses, DAFx-08) are the efficient production versions (https://home.mit.bme.hu/~bank/publist/taslp-piano/index.html, https://dafx.de/paper-archive/details/5mJ31JDQWZTHNiqjmf19mQ). Pianoteq advertises sympathetic resonance of all strings "at a fundamental level" (https://www.modartt.com/pianoteq_features, https://www.soundonsound.com/reviews/modartt-pianoteq). The 1990s single-string-emulator sympathetic patent (US 5,468,906) uses fixed-gain one-way injection (https://patents.justia.com/patent/5468906).
** (c) Mixing-matrix choice, and what to do when N changes
The following is derived from the theorems above and checked in my toy test. "Sum into everyone" on top of each string's own loop, w_i = v_i^+ + c * sum_{j != i} v_j^+, has matrix I + c(1 1^T - I). Its in-phase eigenvalue is 1 + c(N-1), always above 1. Every string's loop gain g is close to 1 at its partials, and close to 1 at DC unless DC is blocked, so the in-phase mode at any shared frequency grows when g(1 + c(N-1)) > 1, that is, when c > (1-g)/(g(N-1)). For g = 0.9995 and N = 32 that means c above about 1.6e-5. So naive coupling must be tiny and must still shrink as 1/N.

The junction instead subtracts: w_i = v_i^+ - alpha * sum_j v_j^+. The own term (1 - alpha) and the cross terms (-alpha) together form an orthogonal or passive matrix, so the coupling only redistributes energy.

On renormalisation when N changes: 1/N, as the junction's 2/(N + r) does, holds the in-phase loop gain constant, and coherent coupling is what causes runaway. 1/sqrt(N) holds the power of an incoherent sum constant, which is right for loudness of an uncorrelated mix (the reason Hadamard matrices are scaled by 1/sqrt(N) to be orthogonal, https://ccrma.stanford.edu/~jos/pasp/Householder_Feedback_Matrix.html). But with all-ones coupling, 1/sqrt(N) lets the in-phase gain grow as sqrt(N), so adding notes can push it unstable. A fixed per-pair coupling is fine only when a large bridge term keeps the total passive (r >> N).

Recommendation: use alpha = 2/(N + r) with r as the "bridge heaviness" knob. Large r gives piano-like weak, fixed-per-pair coupling; small r gives strong coupling that self-normalises. N may change at any sample: removing a note's delay line removes energy, adding one with an empty line adds none, and each per-sample scattering is norm-non-increasing. So the stored energy (the sum of squares of all delay-line contents) cannot grow from re-sizing alone. This is my argument (UNVERIFIED in the literature; it is consistent with the time-varying FDN work above). Fractional-delay retuning breaks exact losslessness slightly. Keep each string's loss filter |G_i(e^jw)| < 1 so the whole network is strictly passive.
** (d) Nonlinearity in the loop
Smith's electric-guitar model: "the amplified guitar waveforms couple back to the strings with some gain and delay". The "Amplifier Feedback Delay ... can be adjusted to emphasize certain partial overtones over others". If loop gain exceeds 1 at any frequency, "a sustained feedback howl will be produced". Distortion sits between frequency-dependent pre- and post-gains, for example an integrator g/(1 - r z^-1) before it and a differentiator (1 - r z^-1) after (https://ccrma.stanford.edu/~jos/pasp/Amplifier_Feedback.html, after Sullivan 1990). The soft clipper is f(x) = x - x^3/3 for |x| <= 1, and +/-2/3 outside (https://ccrma.stanford.edu/~jos/pasp/Soft_Clipping.html). Tube-like asymmetry (duty-cycle shift, a DC offset into the clipper) adds even harmonics (https://ccrma.stanford.edu/realsimple/SimpleStrings/Amplifier_Distortion_Amplifier.html).

The moForte GeoShred "Sympathetic Resonator" is close to Jeff's spec. Its "Coupling" control links the resonator strings to each other. "Level" is the "feedback gain that scales the sum of all string outputs before they are delayed and summed into all strings". "Drive" adds distortion. "Distance" is the distance in feet from an amplifier speaker that feeds back into the strings. (This was quoted by search from https://www.moforte.com/geoShredAssets5.0/help/effects/stringVerb-drone.html; direct fetch returned 404 on 2026-10-27, so the wording was not fetched first-hand. GeoShred grew out of the Geo Synthesizer, co-created by Rob Fielding: https://apps.apple.com/us/app/geo-synthesizer/id465224352.)

Why a bounded nonlinearity tames runaway (my argument): if the cross-path is u = k * tanh(G * sum_j y_j) and each resonator alone is stable (finite l1 norm ||h_i||_1), then |u| <= k, so |y_i| <= k * ||h_i||_1 + (own excitation term). The system is BIBO-bounded for any G and any delay. The price is that it may never decay: the howl is a limit cycle. A clipper inside each string's own loop (Elements Tube's CONSTRAIN +/-5) bounds that loop the same way.
** (e) Latency: sample-by-sample or block-based?
The passive junction must be sample-accurate with respect to the loop delays. Processing in blocks of B samples is exact, and identical to per-sample processing, as long as B is no larger than the shortest loop delay among the coupled notes. Within such a block every delay-line read only touches samples written at least B samples earlier, so all reads come first, then the junction runs vectorised, then all writes. This is standard practice (block size capped at the shortest delay, or sample-by-sample recursion) but I found no formal citation (UNVERIFIED; see the discussion in https://forum.hise.audio/post/55267 and https://lists.w3.org/Archives/Public/public-audio/2012AprJun/0290.html). At 48 kHz, piano C8 (4186 Hz) has a period of 11.5 samples, so B <= 8 to 11.

Inserting a whole audio buffer of delay into the coupling path instead is NOT safe. The derivation: delay only the cross terms by B, giving S(z) = (1 - alpha) I - alpha z^-B (1 1^T - I). Then S is no longer paraunitary for N > 2, and its in-phase eigenvalue reaches |(1 - alpha) + alpha(N-1)| at frequencies where z^-B = -1. With alpha = 2/N that is |3 - 4/N|, so the gain approaches 3. In my toy test, B = 64 diverged within seconds at r = 0 and grew about 13x per 5 s even at r = 200. Delaying the whole bridge sum diverged as well.

The cpal callback buffer therefore only sets control latency. The synth must run its internal coupling per sample, or per micro-block of at most 8 samples, inside the callback. The one path that can use a big delay is the saturated "amp" path in (d): it is bounded, and its delay is physically meaningful (64 samples is 1.33 ms, about 0.46 m of air at 343 m/s; that arithmetic is mine).

Measured cost, from my own code on this 16-core box: 32 waveguide strings at 48 kHz with linear-interpolated delays, a two-tap loss filter and the O(N) junction ran at about 1% of one core (0.09 to 0.33 s for 10 to 30 s of audio). Per-sample processing is cheap. A dense N x N matrix would be 1024 multiply-adds per sample instead of about 64, still affordable but pointless when the structure is rank-1.

* D. The "Marshall stack" character
** Ingredients
Three things are needed. The first is loop gain at or above 1 in some band, so notes sustain or grow instead of decaying (Smith's "feedback howl" condition, above). The second is a saturating nonlinearity in that loop, which sets the steady amplitude and adds harmonics: odd harmonics from symmetric clipping, even ones from asymmetry (https://ccrma.stanford.edu/~jos/pasp/Soft_Clipping.html, https://ccrma.stanford.edu/realsimple/SimpleStrings/Amplifier_Distortion_Amplifier.html). The third is mode and frequency locking, so near-harmonic partials of different notes pull into exact ratios and the chord fuses into one roaring tone. Fletcher showed that nonlinearly excited, slightly inharmonic modes lock into an exact harmonic series. Locking is likelier when the modes are nearly harmonic, when amplitudes are large, and when the nonlinearity is strong (JASA 64:1566, 1978, https://www.phys.unsw.edu.au/music/people/publications/Fletcher1978.pdf; the PDF is a scan, so this is the abstract-level claim). Two organ pipes of different pitch frequency-lock as coupled self-sustained oscillators, with a "hump" spectrum from nonlinear beating, and the locking region is an Arnold tongue (https://arxiv.org/abs/physics/0506094, https://pubmed.ncbi.nlm.nih.gov/27794343/). Long sustain also lets the amp-feedback delay choose which partial wins (Smith: the feedback delay "can be adjusted to emphasize certain partial overtones").
** Rob Fielding's oud-driven resonator bank
I could not find any public write-up of it (UNVERIFIED; the only source is Jeff's account). The GeoShred Sympathetic Resonator (sum, Level, delay, broadcast, Drive) is the closest documented relative, and plausibly shares its lineage, since Fielding co-created the Geo Synthesizer's playing surface (UNVERIFIED link).
** Getting it on purpose
A controllable design, assembled from the sources above. Use passive strings (waveguide or modal) coupled by the junction alpha = 2/(N + r), which is always stable. Add one global amp path: y_amp = k * f(pre_eq(G * sum_i v_i^+)) delayed by D, then added to every string. Here f is tanh or the cubic clipper (offset input for even harmonics), D is 1 to 10 ms (the speaker distance), and k/N scaling keeps character constant as notes change. Turning G past the howl threshold gives infinite sustain. The saturator bounds the level; partials shared by several notes (unisons, octaves, fifths) dominate because the in-phase mode has the most loop gain; and near-misses lock. My toy run (G = 50, D = 256 samples, k = 0.01) held a sustained bounded tone for 30 s instead of decaying.
** Avoiding it
Keep every loop strictly passive: junction with r > 0 and loss filters below 1. Use no gain stage in the cross-path, or keep G below threshold. Put the saturator only on the output. Block DC in each loop, because the in-phase DC mode is the first to run away. Note also that locking fights deliberate microtonal detuning: in 58-EDO, near-unisons and near-octaves between held notes will be pulled toward just ratios when the loop is active and saturated. That follows from Fletcher and Abel et al.; I have not tested it.
** Blown models in the bank
Coupling self-oscillating winds or brass all-to-all is coupling oscillators, not resonators. Expect pitch pulling, frequency locking within Arnold tongues, quasi-periodic beating, and register jumps, as in the organ-pipe synchronisation papers above. The STK Brass loop, where pitch already comes from a fragile lip-versus-bore balance, is the most likely to "sound nasty". Jeff's suspicion is consistent with the literature (UNVERIFIED by listening). If winds are wanted, use them as one-way drivers into a passive bank, the way Rings' string 0 drives its sympathetic strings, rather than as members of the all-to-all bank.

* My own toy test (my code, not literature)
Location: /tmp/claude-1000/-home-ubuntu-host-worktrees-main/d70b5487-740e-4a44-9ca9-58a4a9cf6c29/scratchpad/bench_coupling/src/main.rs. Setup: 32 strings at 27.5 Hz to 5.3 kHz with unisons, octaves and fifths; loop gain 0.9995; 20 ms noise burst into all strings; 30 s run.

Results:
Uncoupled: decays.
Junction r = 0 (Householder): decays (peak 0.26, then 1.2e-3 in the last second).
Naive additive coupling, c = 1/N, c = 1/sqrt(N) or c = 0.002: diverges immediately.
Naive c = 1e-5: stable.
Junction with cross terms delayed 64 samples: diverges (r = 0), or grows about 13x per 5 s (r = 200).
Junction with cross terms delayed 8 samples, r = 200: stable.
Whole bridge sum delayed 64 or 256 samples: diverges.
Global tanh amp path, G = 50, delay 256: bounded (about 550) and sustained indefinitely.
#+begin_src rust
// junction (lossless at r=0, passive for r>0); O(N) per sample
let vb = 2.0 / (n as f32 + r) * sum;            // sum = sum_i v_i^+
for i in 0..n { s[i].write(vin[i] - vb); }      // write v+ - v_b (nut inversion folded in)
// amp path: bounded by tanh, so any delay is safe
let amp = (gain * sum_delayed).tanh() * 0.01;
for i in 0..n { s[i].write(vin[i] + amp); }
#+end_src
