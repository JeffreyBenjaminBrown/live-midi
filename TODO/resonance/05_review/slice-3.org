* Deviations from the plan's "how"
** A 'knock_mix' of 0 empties the voice's knock, not the table
'knock_table' no longer reads 'knock_mix', so the shared table
is never empty for that reason (moving 'knock_mix' off 0 must
not rebuild it). 'ExcitationStream::new' takes the scale and
drops the knock when the scale is 0, so the voice's stream is
the dry table alone and ends with it, as before.
** The scale is one function
'voice::knock_scale_at_birth(&StringsParams)', called by
'StringVoice::new' and 'ModalVoice::new'. Their signatures are
unchanged; they read the scale from the 'params' they already
take, so the tests that build voices directly needed no edit.
** 'set_mix' restarts the resonators when leaving mix 0
A bank at mix 0 skips its resonators. 'set_mix' from 0 to above
0 resets them, as a new bank would start, so a pedal sweeping
'body.mix' up from 0 does not resume a state from long ago.
Between two mixes above 0 they keep ringing.
** The field-wise comparisons are two named functions
'body_shape_changed' (every body field but 'mix') and
'knock_exciter_fields_changed' ('brightness', 'knock_ms') in
'renderer.rs'; the knock rebuilds on either, the bank on the
first.
** The test accessor
'StringsRenderer::shared_knock_table() -> &Arc<[f32]>' is 'pub'
(not test-only); the tests compare it with 'Arc::ptr_eq'.
** The "before" render covers both voice kinds
A 220 Hz note (loops) and a 3000 Hz note (modal, above the
default 2000 Hz crossover), each struck alone at the defaults
and rendered for 1 s. Measured at f717fb0's code (HEAD
'a17a2a9' differs from it only in the plan): 220 Hz peak
1.525116712e-1, energy 5.650005450e1; 3000 Hz peak
6.011803448e-2, energy 1.139704978e0. After: relative changes
about 4e-7 (peak) and 1.5e-5 (energy) at 220 Hz.
** The growing ebow note needs a slow growth rate
'a_floor_of_one_keeps_an_ebow_note_growing_after_its_leg' sets
'growth_rate_per_second_max' to 1 and 'pick_energy' to a
hundredth of 'drive_limit': at the default 8 nepers per second
the note reaches the tanh within a second and sits there, so
"still growing at 3 s" could not be observed. Growth is RMS over
100 ms around 3 s above that around 2.5 s.
** Doc comments beyond the plan's list
'params.rs' 'knock_mix' no longer says the knock is "convolved
into the table"; 'ex_post_energizing_ms' says the window falls
to the floor. 'renderer.rs''s module comment no longer says the
factor goes only to voices in their ex-post leg. 'energy.rs''s
ebow paragraph says "while the window is open".

- What the rig text (slice 5) should say: the window falls over
  the ex-post leg to the floor instead of to 0 and stays there,
  so above 0 the pedal feeds a note for as long as it sounds,
  at 'floor * pedal ^ pedal_energy_exponent'. For the ebow the
  note grows to its limit instead of settling when that factor
  exceeds 'decay / (growth_rate_per_second_max + decay)',
  'decay = ln(1000) / T60(f0)' nepers per second. At the
  default T60s and a growth rate of 8: about 0.08 at 55 Hz,
  0.16 at 220 Hz, 0.37 at 1760 Hz (the bridge's drain raises
  these a little). The trade: sustained notes under a held
  pedal never die on their own. A voice keeps the energy
  parameters of its birth, so a floor target shapes the next
  note, not the sounding one.
