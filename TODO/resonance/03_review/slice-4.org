* Deviations from the plan's "how", with reasons
** The schema is StringsParams' own nested structs
The brief asked for separate 'StringRig', 'ExciterRig' and so on
with a conversion. Their fields would all equal the params'
fields, a second copy of seven field lists to keep in step. The
params structs already name their fields as the rig keys, so they
derive 'Deserialize' with 'default, deny_unknown_fields', and the
sink's fields are 'string: StringParams' and so on. Each table's
'Default' reads 'StringsParams::default()', so every number has
one copy. 'SinkRig::strings_params' builds the 'StringsParams'.
This makes 'strings/params.rs' depend on serde, nothing more.
** The sink's two time constants are the scripted voices'
The rig's default 'release_secs' is
'scripted_voices::RELEASE_SECS', and the strings 'attack' in
'resolve_sink_settings' is 'STRIKE_ATTACK_SECS'. Both constants
already said they were a strings sink's values. Using them keeps
one copy of each.
** 'resolve_settings' gets a helper, not a second destructure
'resolve_sink_settings' returns a private 'SinkSettings' (the
fields the sink decides), one match arm per accepted kind. The
'Settings' literal reads from it.
** The harness also takes the rig's amplitude
Not only the params and sample rate: 'what it renders is what the
rig plays' needs the sink's loudness too. Without a rig it uses
the old 0.15.
** Dispatch: a strings sink makes a rig a surfaces rig
'is_surfaces_rig' needed two grids, drums or a selector. A
one-grid strings rig would have matched nothing and printed "no
runnable runtime path". Only surfaces runs the strings engine, so
a 'cpal_strings' sink now qualifies. No shipped rig changes
runtime (the dispatch tests by rig name still pass).
'print_startup' and the other 'cpal_synth' messages
('sawwave_runtime', 'looper_runtime') are right as they are.
** The engine is chosen at start
If a reload's rig has no strings parameters (another sink kind),
the callback keeps the strings parameters it has; switching
engines needs a restart. The reload message says so.
** audio.rs builds both renderers
'BlockRenderer::new(oversample)' is still built on a strings rig
and never used, so the sawwave path is unchanged line for line.
It costs one small allocation at start.
** Extra tests
A decayed, held string keeps its string voice (the reaper's
opposite). An org rig with the strings tables under grouping
headlines loads. A sawwave rig resolves with 'strings' 'None'.
