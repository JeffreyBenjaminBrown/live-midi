** What are the loop controls?
*** Codex : what the implemented looper has
There are two useful answers: the small transport, and the much larger editing
interface around it.

The core controls are:

- a bank of slot buttons, one of which is /active/;
- START, which begins recording into the active slot and overwrites its old
  contents;
- STOP, which finishes a recording without playing it, or stops the active slot
  if it is playing;
- PLAY, which finishes a recording and plays it, or starts an already-recorded
  active slot.

Selecting a slot only changes which slot those controls address.  It does not
start or stop anything.  In the present looper, only one loop can sound at a
time, PLAY replaces the previously sounding loop, there is no overdub, and
there is no erase gesture: recording over a slot replaces it.  The slot LEDs
are active solid > sounding-but-not-active flashing > occupied dim > empty
black.

The existing 4x4 slot rectangle puts START, STOP, and PLAY over three cells in
its bottom row.  Thus it allocates sixteen slots but only thirteen can actually
be pressed.  The proposed 2x8 rectangle can use exactly the same trick: sixteen
nominal cells, three transport overlays, thirteen reachable slots before a
sustain-button overlay is counted.

The full looper additionally has:

- COPY (press COPY, a source slot, then a destination);
- a fine/group-transpose remap toggle;
- undo-last-remap;
- a time-by-pitch loop display whose top row, left column, and body select time
  columns, pitch rows, and individual events for remapping; and
- the note grid as the destination-pitch picker during a remap.

Those editing controls occupy much more than 2x8.  In fact, the current config
requires a =loop_display= in addition to slots and transport.  So the compact
layout can inherit the core transport, but cannot inherit the whole current

**** Codex : compact loop-control state machine

- START LOOP RECORDING: immediately begin freehand recording into the selected
  slot.  It replaces that slot when the recording is finalized.  If the same
  slot was sounding, stop it first.  A different sounding slot continues, but
  its playback is excluded from the new recording.
- STOP LOOP RECORDING/PLAYBACK: if the selected slot is recording, finalize it
  without playing it.  Otherwise, if the selected slot is sounding, stop it.
  Otherwise do nothing.
- PLAY LOOP: if the selected slot is recording, finalize it, stop the old
  sounding loop, and start the newly recorded loop at phase zero.  Otherwise,
  if the selected slot is populated, stop the old sounding loop and start the
  selected loop at phase zero.  An empty selected slot does nothing.

continues.  STOP LOOP RECORDING/PLAYBACK stores B and leaves A sounding; PLAY
LOOP stores B, stops A, and makes B the sole sounding loop.  START LOOP
RECORDING and PLAY LOOP both flash during the overlap.

previously stated: I have treated PLAY LOOP on an already sounding selected

** Codex : latest loop layout and control model

#+begin_example
       chord half, x=0..7                  loop half, x=8..15
y=14   C C C C C C C ACCRETE              CLEAR-SUSTAIN START-RECORD L L L L L L
y=15   C C C C C C CHORD-MODE ARM-CHORD   STOP  SELECT-RECORD L L L L L PHASE-MODE
#+end_example

There are thirteen chord slots and now eleven loop slots.  Loop slot 1 is
=(10,14)= and is the record target at startup.  A normal populated-slot touch
toggles only that slot's playback; any number may sound.  SELECT RECORD TARGET
causes the next slot touch to retarget recording without changing playback.
START LOOP RECORDING and STOP LOOP RECORDING control recording only.

An empty target's duration is =STOP - START=.  A populated target is overdubbed
without changing its duration.  A sub-threshold START/STOP clears the target;
a normal first take containing no intervals also leaves it empty.  Playback
never feeds either recorder.  Reconstructed voices attack through the ordinary
envelope and stopped voices release through it, so slot gating has no hard
amplitude discontinuity.

The PHASE MODE corner flashes in KEEP-RUNNING and is black in RESTART.  Every
slot starts dormant at phase zero.  KEEP-RUNNING preserves an advancing phase
after the first trigger when playback is later toggled off; RESTART returns it
to phase zero.  Stored loop contents persist, but playback starts silent and
phase returns to dormant zero on every program launch.
