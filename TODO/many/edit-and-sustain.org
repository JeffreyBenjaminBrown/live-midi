* DONE claude: the spec I extract from this
Restated so you can tell me where I have misread you. I have used "voice" throughout,
never "note", per your rule.

** identity
A voice is identified by a VoiceId, and by nothing else. The VoiceId is opaque and
unique, and it never changes over the voice's life.

Pitch is not an identity, because a voice's pitch changes. A monomekey is not an
identity either, because the display scrolls, so the monomekey under the finger is not
where that voice's pitch is drawn any more.

A monomekey is instead an index into the fingered voices: it is how a lift finds the
voice to end. That index is what "a fingered voice can be identified by the monomekey
that originally pressed it" means, and it is the same reason the old code kept a
cell-to-pitch map.

** the two sets
The sustained set holds VoiceIds. The edit set holds VoiceIds. Both are per grid.

Neither set holds pitches, and that is the substantive change.

** the properties
A voice sounds while a finger holds it, or while it is in the sustained set. Those are
the only two reasons a voice sounds.

Edit is a property of a voice and not a reason for one to exist. A voice in edit mode
that loses its last reason to sound simply dies, and its edit property dies with it.

** the gestures
Pressing the monomekey above a voice adds it to the sustained set, and pressing it
again removes it. Pressing the monomekey below a voice toggles its edit property.

Where several voices sound the same pitch, both gestures act on all of them, because
nothing in the gesture distinguishes them.

** clearing
Clear-sustain empties the sustained set for one grid, and it does not touch fingered
voices. Clear-edit empties the edit set for one grid, and it does not silence anything.

* DONE claude: what this model deletes, which is the real argument for it
Making edit a property rather than a reason removes the bug class that has produced
three of the five hardware failures, and it removes it structurally rather than by
care.

Edit mode could previously outlive the thing it edited. A clear silenced a voice and
left its pitch in the edit set, so the grid kept dancing around a voice that was not
there, every press dragged instead of playing, and the gesture that would have
dismissed it required the voice to be audible. Nothing could reach it.

Under your model that state cannot be built. The edit property lives on the voice, so
it cannot outlive the voice any more than a colour can outlive the thing it painted.
Clear-sustain kills the voices, and their edit properties go with them.

It also deletes the ownership bookkeeping. I had a flag recording whether edit mode was
the reason a voice rang, so that leaving edit mode knew whether to silence it. That flag
exists only because edit was pretending to be a reason. It goes.
