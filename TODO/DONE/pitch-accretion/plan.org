#+TITLE: Plan: monome chord accretion (v1)
#+DATE: 2026-04-25

* Goal

Add a "generalized sustain pedal" to grid_synth: a single in-memory
*accretion slot* of EDO pitches, plus four control keys that
populate/silence/clear it and toggle whether its contents sound. A
fifth control key changes the mode of the emit key. A Reason-based
LED model keeps every cell's lit state correct as voices come and
go, including the existing pitch-class equivalence lighting.

This is v1. Multiple slots / chord storage, brightness, LED-state
restore on USB re-enumeration, and any "slot non-empty when emit
off" indicator are deferred.

* Types

#+begin_src rust
  // --- existing, unchanged ---
  type EdoPitch = i32;
  type Cell = (i32, i32);

  // --- new ---
  type VoiceId = u64;
  type Rect = (Cell, Cell);  // inclusive corners

  enum VoiceSource {
    Fingered { xy: Cell },
    Accreted { pitch: EdoPitch },
  }

  struct VoiceState {
    id: VoiceId,
    freq: f32,
    phase: f32,
    env: f32,
    target_env: f32,        // 0.0, 0.5, or 1.0
    ramp_per_sample: f32,   // |Δenv per sample|; recomputed when target changes
  }

  type VoiceMap = HashMap<VoiceSource, VoiceState>;

  // First-insertion-wins: the set is initialised when P first enters
  // the accretion and never grown afterwards. Wipe clears the whole map.
  type PitchAccretion = HashMap<EdoPitch, HashSet<VoiceId>>;

  enum LedReason {
    PitchEquivalent { source_xy: Cell },   // a fingered key at xy is held
    Accretion        { pitch: EdoPitch },   // P is in PitchAccretion AND emit is on
  }

  // Sparse: only cells with ≥1 reason appear here.
  type LedReasons = HashMap<Cell, HashSet<LedReason>>;

  // Three behavioural shapes for control keys.
  enum Button {
    Toggle { state: bool, on: ButtonRole, off: ButtonRole },
    Nursed { state: bool, on: ButtonRole, off: ButtonRole },
    Fire   { fire: ButtonRole },
  }

  // A small enum of "what does this button do" — dispatched by the
  // World, not stored as closures (which fight the borrow checker).
  enum ButtonRole {
    AccreteOn, AccreteOff,
    EmitOn,    EmitOff,
    SilentFire,
    WipeFire,
    EmitIsToggleOn, EmitIsToggleOff,
  }

  // A window is a rectangle of cells routed to one named handler.
  // World stores them front-to-back: an event hits the first window
  // whose rect contains the cell. An LED command from window W to
  // cell C is forwarded only if C is in W's rect AND no earlier
  // window's rect contains C. Dispatch is by `id` — the EDO window
  // runs the pitch-grid handler; control windows look the cell up
  // in their own button map (kept on World, see below).
  struct Window {
    id:   WindowId,
    rect: Rect,
  }
  enum WindowId { Edo, Accretion2x2, EmitToggle1x1 }

  struct World {
    voices:           VoiceMap,
    pitch_accretion:  PitchAccretion,
    emit_on:          bool,
    accrete_on:       bool,
    emit_is_toggle:   bool,        // true ⇒ emit Button is Toggle; false ⇒ Nursed
    next_voice_id:    VoiceId,
    pitch_class:      PitchClass,  // existing struct
    led_reasons:      LedReasons,

    // Front-to-back; the dispatcher walks this list to route events.
    windows:          Vec<Window>,
    // Per-cell button maps for the control windows. Looked up only
    // when the dispatcher's match on Window.id lands on the
    // matching variant.
    accretion_buttons:   HashMap<Cell, Button>,  // cells in the 2x2
    emit_toggle_button:  Button,                 // the single (2,15) cell

    // tuning, sample rate, etc. — same as today
  }
#+end_src

* Behavioural rules

** Startup: integer-only tuning

=edo=, =x_step=, =y_step= are *required* to be integers (parse as
=i32=); =fund= stays =f64= (it's a continuous frequency in Hz). If
any of the three integer args is missing or unparseable, panic with
a helpful message at startup and exit. With this guarantee every
=pitch_class.key_to_pitch[C]= is an exact integer — no floating-
point jitter, no per-press "is this integer?" branch.

The existing pitch-class lighting code's "non-integer fallback"
branch (=Some(build_pitch_class_maps(...))= vs =None=) becomes dead
code; delete it.

** Press of cell C in EDO grid window
- Compute pitch =P = pitch_class.key_to_pitch[C]=.
- Generate =id = next_voice_id; next_voice_id += 1=.
- Insert =Fingered{xy:C}= → fresh =VoiceState{ id, freq, phase=0,
  env=0, target_env=1.0, ramp_per_sample=1/(0.003·sr) }=.
  (Per Jeff's choice (b): retrigger always issues a new id and
  resets env/phase. Old voice at same xy is dropped.)
- If =accrete_on= and P is *not yet* in =pitch_accretion=:
  insert =P → {id}= into =pitch_accretion=.
  If =emit_on=, also add =LedReason::Accretion{P}= to every cell
  in =pitch_class.pitch_to_keys[P]= (see LED diff below).
- For every cell C' in =pitch_class.pitch_to_keys[P]=, add
  =LedReason::PitchEquivalent{source_xy:C}= to =led_reasons[C']=.

** Release of cell C in EDO grid window
- Compute pitch =P = pitch_class.key_to_pitch[C]=.
- For every cell C' in =pitch_class.pitch_to_keys[P]=, remove
  =LedReason::PitchEquivalent{source_xy:C}= from =led_reasons[C']=.
- Look up the finger voice at =Fingered{xy:C}=; its id is =id=.
- Decide its target_env. Let
  =originvoices_for_P = pitch_accretion.get(&P)= and
  =other_originvoices_alive(P, id) = originvoices_for_P.contains some
  id' ≠ id whose voice is still in =voices=.=
  - *Transform* (=target_env = 0.5=,
    =ramp_per_sample = |env − 0.5| / (0.05·sr)=, and rekey the
    HashMap entry from =Fingered{xy:C}= to =Accreted{pitch:P}=) iff
    *all* of:
    - P is in =pitch_accretion=,
    - =emit_on=,
    - no =Accreted{P}= voice currently exists,
    - =originvoices_for_P= contains =id=,
    - *no other live originVoice for P*: =not
      other_originvoices_alive(P, id)=.
  - *Else:* ramp to 0 — =target_env = 0=,
    =ramp_per_sample = env / (0.05·sr)=.

The "this is the last alive originVoice for P" condition handles
the case where two enharmonic keys both first-introduced P:
releasing the first one ramps to 0 (the other is keeping P alive);
only releasing the second triggers the transform.

** accretion-accrete press (Toggle)
- *Off → on:*
  - =accrete_on = true=.
  - *Atomic snapshot.* Group all currently-held finger voices by
    pitch. For each pitch P with at least one held finger voice:
    - If P is *not* in =pitch_accretion=: insert =P → {set of ids
      of all held finger voices for P}=. (Multiple held enharmonic
      keys all become co-originVoices in this single event.)
    - If P *is* already in =pitch_accretion=: do nothing — leave
      the existing originVoice set alone. (P was introduced by an
      earlier event; this snapshot doesn't grow it.)
  - If =emit_on=: for each newly-introduced P, add
    =LedReason::Accretion{P}= reasons (see LED diff).
- *On → off:*
  - =accrete_on = false=. =pitch_accretion= is unchanged. No voice
    changes.

** accretion-emit press (Toggle or Nursed, depending on =emit_is_toggle=)
- *off → on:*
  - =emit_on = true=.
  - For each P in =pitch_accretion=: if there is *no* alive finger
    voice whose id is in =pitch_accretion[P]= (i.e., no originVoice
    for P currently held), spawn an =Accreted{P}= voice with
    =target_env=0.5=, =env=0=, =ramp_per_sample=0.5/(0.003·sr)=.
    Otherwise skip (the held finger voice will transform on
    release).
  - For each P in =pitch_accretion=, add =LedReason::Accretion{P}=
    to every cell in =pitch_class.pitch_to_keys[P]=.
- *on → off:*
  - =emit_on = false=.
  - For every =Accreted{P}= voice: =target_env=0=,
    =ramp_per_sample = env / (0.05·sr)=.
  - Remove all =LedReason::Accretion= reasons from =led_reasons=.

** accretion-silent press (Fire)
- Identical effect to "emit on→off" *if* =emit_on=. Plus =emit_on
  = false=. (Comment in code: pressing silent while emit is in
  Nursed mode is silly — just release the emit key.) If =emit_on=
  is already false, no-op.

** accretion-wipe press (Fire)
- =pitch_accretion= cleared. Every =Accreted{P}= voice ramped to 0
  (target=0, same ramp as emit-off). All =LedReason::Accretion=
  reasons cleared. =emit_on= unchanged.

** accretion-emit-is-toggle press (Toggle)
- Flips =emit_is_toggle=. Snapshot semantics: =emit_on= is *not*
  touched; whichever state it was in, it stays. The =Button= for
  emit is rebuilt with the new variant on next dispatch.
- Light/darken the (2,15) LED to match =emit_is_toggle=.

* Voice rendering (per-block, in =render_block=)

For each =VoiceState= in =voices.values_mut()=:
- Advance =env= toward =target_env= by =ramp_per_sample= (clamped at
  target).
- Advance =phase= by =freq / sample_rate= (mod 1.0).
- Mix =triangle(phase) * env * AMPLITUDE * source_scale= where
  =source_scale= = 1.0 for Fingered, 0.5 already encoded in
  target_env for Accreted (so source_scale=1.0 always — env carries
  the half-volume).
- After the loop, drop voices where =env == 0.0 && target_env ==
  0.0=.

(=source_scale= note: I'm folding the 1/2 accretion volume into the
voice's =target_env= rather than a separate scalar. Simpler render
loop, same audible result.)

* LED diff helpers

Two pure helpers, exercised in isolation by tests:

#+begin_src rust
  // Given the led_reasons map and a (cell, reason) to add or remove,
  // mutate the map AND return the cell-level transition (None, Some(true)
  // for newly-lit, Some(false) for newly-dark).
  fn add_reason(reasons: &mut LedReasons, cell: Cell, r: LedReason) -> Option<bool>;
  fn remove_reason(reasons: &mut LedReasons, cell: Cell, r: LedReason) -> Option<bool>;
#+end_src

Every press / release / emit / wipe / silent goes through these.
Cells whose set transitions empty→nonempty get a =compositor.set_led(EDO,
cell, true)=; nonempty→empty gets =false=.

* Implementation order

To keep each step small and reviewable, I'll commit in this order:

1. *Remove the click.* All deletions, no new behavior. Tests
   shrink. Verify =cargo test= still passes.

2. *Refactor voices to =HashMap<VoiceSource, VoiceState>=
   with =target_env= / =ramp_per_sample= envelope.* No new
   behavior; existing tests adapted. New attack ramp 3 ms (was
   5 ms); new accretion volume scaffolding present but unused.

3. *Introduce =Vec<Window>= + dispatch + Buttons skeleton.* The EDO
   window wraps the existing handler unchanged; the 2×2 and 1×1
   windows have buttons whose actions are *no-ops* at this stage.
   New tests for dispatch and visibility pass.

4. *Wire the LedReasons model.* Pitch-equivalence reasons replace
   the current =pressed: HashSet=-driven LED logic. Existing
   lighting behavior preserved. Existing tests reframed.

5. *Implement accretion state machine.* Accrete / emit / silent /
   wipe / emit-is-toggle actions hooked into ButtonRoles. Voice
   spawn / ramp / transform rules from §"Behavioural rules" land.
   All accretion tests pass.

6. *Final pass:* keymap / layout numbers double-checked, comments
   for the "silent in Nursed mode is silly" pitfall and the
   "junk reasons across windows" pitfall, manual smoke test on
   the actual grid.

Each commit ends with =cargo test --release= green.
