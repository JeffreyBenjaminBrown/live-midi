* the answer up front
Yes, the note is bad -- and nothing on your host broke. The line

#+begin_example
xhost --run 'xhost +local:'   # per login, not per use of a rig
#+end_example

is a *truncated copy of a =nix-shell= one-liner*. The original, from our July
conversation ([[file:../many/2_discussion.org::*DONE run =xhost +local:= on the host (installing it is not enough -- see below)][TODO/many/2_discussion.org, the "run xhost" thread]], line 695), was:

#+begin_src sh
nix-shell -p xorg.xhost --run 'xhost +local:'   # one-off, per login
#+end_src

=--run= is *nix-shell's* flag ("run this command inside the shell"), not
xhost's. When the =nix-shell -p xorg.xhost= prefix fell off in the copy to your
notes, what remained hands =--run= and the literal string =xhost +local:= to
=xhost= itself as arguments -- and =xhost= parses every argument as a
=[+|-][family:]name= host spec. Hence the three errors, one per misread token:

- =bad hostname "-run"= :: leading =-= means "revoke access for host ...", so it
  tried to resolve a host named =-run=.
- =unknown address family "xhost +local"= :: the quoted string contains a colon,
  so everything before the colon is read as an address family.
- =bad hostname "xhost +local:"= :: the fallback: the whole string as a hostname.

So the command *never worked as written, under any system config*. That is also
why your discarded hypothesis was rightly discarded: reverting to an earlier
NixOS generation couldn't help, because no generation was at fault.

* the second wrinkle: the nix-shell wrapper was never needed anyway
The July thread went one step further after that one-liner was prescribed: it
turned out =xhost= *was installed on your host all along* -- your =packages.nix=
already had the top-level =xhost= package, which is a nixpkgs alias for
=xorg.xhost= (that's the same thread, around line 782; it's also why your
"add =xorg.xhost=" rebuild changed nothing -- same derivation). The =nix-shell=
wrapper was proposed under the mistaken belief that the binary was missing.

So the command your notes /should/ contain is the one the repo docs already
prescribe ([[file:../../rigs/README.org][rigs/README.org]] line 46, [[file:../../rigs/RUNTIME-NOTES.org][rigs/RUNTIME-NOTES.org]] line 52):

#+begin_src sh
xhost +local:            # or the tighter: xhost +si:localuser:jeff
#+end_src

Run it in a terminal *inside your Plasma session* (so it inherits the session's
=DISPLAY= and cookie), once per login. It mutates the running X server's access
list, which is rebuilt at every server start -- that's the "per login" part.
