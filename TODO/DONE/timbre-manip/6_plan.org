* 1. What we are building
Per-note *timbre* control for the monome instrument, editable two ways:
- *live* -- the timbre applied to every note you finger on the edo grid;
- *on the loop* -- editing the stored timbre of notes in a recorded loop.

"Timbre" = everything about how a note sounds except its pitch and timing:
- *waveform* (sine / triangle / square / saw),
- *amplitude* (per-voice volume),
- *slow AM* (amplitude modulation: amplitude/depth, frequency, shape),
- *slow FM* (frequency modulation / vibrato: amplitude/depth, frequency).

Today the synth is monotimbral: =render_block= does =triangle(phase) * env *
amplitude= with one global =amplitude= and one waveform, and =VoiceState= carries
no timbre. The core of this work is making the synth *polytimbral* (timbre per
voice) and giving loops a *per-note* timbre.

The word "amplitude" is used in all three contexts on purpose (overall amplitude;
AM amplitude; FM amplitude) -- intentional overload, settled at [D 2c].

* 2. Concepts and the two editors

** 2.1 Per-voice and per-note timbre
- Each =VoiceState= carries its own timbre (2.5). Voices may differ, so a loop
  note that is a fast-AM square can sound at the same time as a live sine note.
- Each *loop note* stores a full timbre *snapshot*, captured at record time (the
  live timbre active when it was played). A snapshot, not a slot reference: editing
  a slot later never changes already-recorded notes. [D 1b]

** 2.2 The two timbre editors (named by target; placement is inverse)
There is one window kind, =timbre_editor=, with =target = "live" | "loop"=.
- *live-timbre editor* -- =target = "live"=, sits on the *loop* monome. Edits the
  global live timbre (what fingered notes use).
- *loop-timbre editor* -- =target = "loop"=, sits on the *edo* monome. Edits the
  active loop's stored per-note timbre.

You open the editor for X on the *not-X* monome so X stays visible while you edit
it. Each monome's top-left cell opens (unfolds) its editor. The two are *not*
mutually exclusive -- both may be open at once. [D 1d, C 4a]

** 2.3 Live editing (target = live)
Rows show the current live timbre; pressing a cell sets that parameter; it applies
to every note fingered afterward. =sustain-the-edits= and =save-undo= are inert
here (loop-only). A timbre-slot press recalls into the live timbre; =arm= then a
slot captures the live timbre.

** 2.4 Loop editing (target = loop) -- the headline feature
The loop-timbre editor edits the *active* loop (the looper's control-target loop,
matching "the edo grid shows the active loop").

Editing is *destructive*: it rewrites the loop's stored per-note timbre. There are
*two application paths* [C 1a]:

1. *With a selection* (row/column/cell pickers active on the loop display):
   setting a parameter *immediately* stamps it onto *every selected note*. Works on
   a *stopped* loop; no playhead needed. =sustain-the-edits= is irrelevant here.
2. *With no selection* (play-along): each parameter you hold/keep-active rewrites
   *each note-on as the playhead triggers it*. Requires the loop to be playing.

*Display* [C 3e]: each row tracks the lowest still-sounding note of the current
note-group column as the playhead sweeps; on a rest it holds the last value; under
a selection it shows the *lowest selected note's* value instead.

*Parameter states* [C 3g]: a parameter is either *overridden* (your value applies
to new note-ons) or *tracking* (follows per-note stored).
- Held -> overridden; the row shows your held value (steady).
- Released + =sustain-the-edits= ON -> stays overridden; row keeps your value.
- Released + =sustain-the-edits= OFF -> returns to tracking; row resumes following
  the playhead/selection.
- Toggling sustain OFF returns released-overrides to tracking (held ones stay
  until released). Toggling sustain ON is not retroactive.

*Other loop-target controls:*
- A timbre-slot press = *recall whole timbre* onto the edit target (the selection,
  else future note-ons). =arm= then a slot captures the *displayed* timbre. [C 3a]
- The loop-display *corner cell* = *clear selection*. [D 1c]
- The =save-undo= button = checkpoint / one-level undo (2.8).

** 2.5 Synth / voice model
=VoiceState= gains: =waveform=, =gain= (linear), =am { depth, freq, shape }=,
=fm { depth_cents, freq }=, =am_phase=, =fm_phase=. The AM and FM LFO phases reset
to 0 at note-on (per-voice retrigger, so modulation is phase-locked to each
onset). [D 3e]

Per sample, per voice, in =render_block= (after the existing envelope step):
#+begin_example
fm_factor  = 2^( fm.depth_cents * sin(2*pi*fm_phase) / 1200 )
carrier_phase += freq * fm_factor / sample_rate          # wrap to [0,1)
am_phase      += fm.freq... (use am.freq) / sample_rate  # advance LFO phases
fm_phase      += fm.freq      / sample_rate
am_mult    = lerp(1 - am.depth, 1, shaped_unipolar(am.shape, am_phase))
sample     = osc(waveform, carrier_phase) * env * gain * am_mult
mix       += sample
#+end_example
Then clamp the mix to +-0.95 (as today).

- *Oscillators*: =sine=, =triangle= (exists), =square=, =saw=. Band-limit square
  and saw (PolyBLEP) -- a raw square/saw aliases, especially once FM moves the
  pitch. [C 3a]
- *AM* is unipolar in =[1 - depth, 1]= (amplitude = depth; *more = wider* AM;
  depth 0 = no AM, depth 1 = down to silence). Direction reversed from the
  vision, settled at [D 2c].
- *AM shape* morphs within a *config-level* family [D 3c]:
  - =sin_to_square= (default): =tanh(k * sin(2*pi*p)) / tanh(k)=, k from the shape
    row position (k->0 sine, k->inf square).
  - =tri_to_square=: a trapezoid -- triangle whose points widen to flats until the
    sides go vertical, slope from the shape row position.
  Precompute each shape position as a small wavetable; the LFO is sub-audio so
  cost is irrelevant.
- *FM* is a sine vibrato; =fm.depth_cents= is the peak deviation. FM has no shape.
- *amplitude* (=gain=): logarithmic, nominally 6 dB/cell, top cell = unity (=
  today's sink =amplitude = 0.15=); cells below attenuate. Never boost above unity
  (the mixer hard-clips). Part of the saved timbre. [D 3b]

** 2.6 Parameter rows (the UI idiom)
Every parameter is a *row*; pressing the k-th cell sets the value (radio -- one lit
cell = current value, the rest dark). The number of cells comes from the row's
rect width, never a separate field. [D 1a]

Row value mappings are *tagged* in config [C 2c]:
- =linear= -> =[min, max]=, value = lerp across cells. (AM amplitude/depth.)
- =log_factor= -> =[least, multiplier]=; value(k) = least * multiplier^k. The top
  *grows with width* -- desirable for AM/FM frequency (more cells -> higher top;
  audio rate is welcome, [D 2e]).
- =log_range= -> =[least, greatest]=; multiplier = (greatest/least)^(1/(n-1)). The
  *range is fixed*, steps scale with width. Required for the *amplitude row*, which
  is full-width unfolded and narrower in the folded strip yet must keep its range.
- =enum= -> an ordered value list (waveform). (The shape row is a linear morph
  position within the config-level shape family.)

Row order (alphabetical, prose and config) [D 2d]:
AM rows = amplitude, frequency, shape. FM rows = amplitude, frequency.

** 2.7 The window: fold/unfold, layout, occlusion vs reflow
The editor has two states; its top-left cell toggles them. *Folded* is the
resting state (there is no separate hidden state); the folded strip is *always
present*. [D 1d, C 2d]

*Unfolded* (~7 rows):
- row 0: =[ fold/unfold | 4 waveform cells | arm | sustain | save-undo | timbre
  slots... ]= -- 8 fixed cells, then slots fill the rest (8 slots on a 16-wide
  row). =sustain= and =save-undo= are present-but-inert in the live editor (one
  shared layout). [C 3h]
- row 1: the *amplitude* row (full width, =log_range=).
- rows 2-6: the five FX rows in order -- AM amplitude, AM frequency, AM shape,
  FM amplitude, FM frequency.

*Folded* (1 row): =[ fold/unfold | 4 rolling quick-timbre cells | amplitude row
across the rest (=log_range=) ]=. The four quick cells start as the four waveforms
(press = set waveform); once the first timbre is saved they become the *rolling
most-recent-4* saved timbres (newest enters cell 0 and pushes the rest right; the
4th-oldest falls off; recall does not reorder). The strip is in one mode at a time
-- all waveforms, or all timbres -- never mixed. [C 1b, C 4b]
In the loop editor, a folded quick-cell = recall-whole-timbre onto the edit
target; the folded amplitude row = a destructive loop-amplitude edit. [C 3f]

*Placement* [C 3d, C 5a]:
- *Edo monome (loop-timbre editor): occlusion.* The editor is placed with an
  absolute rect and draws over the edo grid. The grid keeps its own rect; the
  rows the editor covers are simply unplayable while covered (1 row folded, 7
  unfolded). Occlusion, not reflow, so fingered notes never move position when you
  unfold. The grid's permanent cost is the one row under the folded strip --
  accepted ("the grid is big").
- *Loop monome (live-timbre editor): reflow.* The editor sits above the looper's
  loop display; the loop display's *top* is anchored to the editor's *bottom*
  (relative coordinates, 4.x), so folding the editor reflows the loop display
  live. No bespoke compound window kind -- two normal windows + a relative anchor.
  [C 5a]

** 2.8 The save-undo button (loop undo)
A =timbre_save_undo= cell in the loop editor (active when =target = "loop"=, inert
in live). Editing is and stays *destructive* (the loop's per-note timbres change
live as you edit); this button only manages *checkpoints* [C 3b]:
- Per loop slot keep =committed= and =prev_committed=, both initialised at record
  time to the as-recorded timbres ("save 0").
- *Single press* (no second within the window): =prev_committed <- committed=;
  =committed <- current=. Sets a restore point.
- *Double press* (second within the window, default 200 ms, configurable): undo --
  restore the live timbres and =committed= back to =prev_committed=, cancelling the
  checkpoint the first tap began.
So a lone tap sets a restore point; a double-tap reverts to the previous one (one
level deep, coarse / whole-slot -- accepted).

** 2.9 LED scheme
The grid shows ~4 brightness buckets (=Brightness::{Off,Dim,Mid,Bright}= in
=types.rs=). [C 2.7, C 3h]
- parameter-row value cell: =Bright=; others =Off=.
- timbre slot: empty =Off=, occupied =Dim=, current =Bright= (flashes 50/50 when
  the live timbre has diverged from it).
- a toggle (=sustain-the-edits=): =Bright= on, =Off= off.
- the fold/unfold cell: =Mid= (always findable, distinct from value cells).
- (Loop reflection / play-mode lighting on the edo grid is the looper's concern.)

* 4. New engine mechanisms (detail)

** 4.1 Relative, per-edge window coordinates
Each rect edge is independently:
- *absolute*: an integer; =-1= counts from the far edge (=-1= = last row/column).
- *relative*: =<window-or-id>.<edge> + offset= (e.g. =live-editor.bottom + 1=).
Absolute rects (today's only mode) still parse. Example -- the loop display
reflowing under the live editor:
#+begin_example
rect.top    = live-editor.bottom + 1
rect.bottom = -1            # monome's last row
rect.left   = 0
rect.right  = -1
#+end_example

** 4.2 The relayout pass
On any fold/unfold, recompute absolute rects for every window with a relative edge
(direct or transitive), in dependency order, then repaint. This is the main new
piece of engine work; nothing today resizes a window at runtime.

* 8. Resolved assumptions (were open in 5_plan §4; now decided)
- *Save = checkpoint.* Editing stays destructive and live; =save-undo= only
  sets/reverts restore points (it is NOT a buffered "apply on save" model). [2.8]
- *No prior save* -> a double-press reverts to the as-recorded timbres
  (record-time capture = "save 0"). [2.8]
- *Top-row budget* -> 8 fixed cells, 8 slots on a 16-wide row; =sustain= and
  =save-undo= are inert in the live editor (one shared layout). [2.7]
