** 1b. Which physical grid is the edo grid and which is the loops grid?
"They are both 16x16 ... already connected, hence hopefully discoverable by you."
Discoverable, yes -- but *indistinguishable*. The current device picker only
matches on size:

#+begin_src rust
// remap_runtime/monome_runtime.rs

  select_size.is_none_or(|[w, h]| device.grid_w == w && device.grid_h == h)

Two 16x16 grids both satisfy =select.size = [16, 16]=, so this picks the same
physical device (the newest serialosc reply) for *both* config monomes. The config

is exactly what you'd use to pin a grid by serial -- but the picker above ignores
it. So today there is no way to say "edo grid is *this* serial, loops grid is

Two consequences for the vision:
- The runtime needs a small change: honor =id_contains= (and ideally

- You then have to *know* each serial, and the ghost-tty / re-enumeration note in
  =RUNTIME-NOTES.org= warns those can churn across replug. So "discoverable by you"
  is true for *a* grid but not for *assigning roles to two identical* grids; that
  assignment has to be written down somewhere stable.

* 2. Contradictions and overloaded signals

** 2a. "each row = one pitch" collides with the pitch-wrap.
Two rules that can't both hold:
- "Each distinct pitch in the loop corresponds to a single row ... each row
  corresponds to a pitch actually played in the loop."
- "If there are more distinct pitches than there are rows ... wrap them. E.g. 8
  rows; pitch 9 maps to row 1, pitch 10 maps to row 2."

Under the wrap, row 1 is *both* pitch 1 and pitch 9. So a row no longer
corresponds to one pitch; the display becomes ambiguous to *read* (when row 1
flashes, which pitch is sounding?), and the modulo mapping also destroys vertical
pitch ordering (row position stops meaning "higher = higher"). The "remap them in
serial, lowest first" complication in section 1f exists *only* as a consequence of
this collision -- a row holds multiple pitches precisely because of the wrap.

This is the design knot I'd most want to untie. Options worth weighing instead of
modulo-wrap: (a) make the display tall enough that wide loops are rare and accept
clipping the rest; (b) scroll/page pitch so each visible row is still one pitch;
(c) keep the wrap but commit to it honestly -- then drop the "each row = one pitch"
sentence and accept that reading and remapping rows is inherently many-to-one.
