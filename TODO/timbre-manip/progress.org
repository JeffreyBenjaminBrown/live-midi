- *Commit order:* do the functional, well-grounded, fully-unit-testable synth work
  (C1, C2) FIRST; do C0 (cosmetic =cpal_sawwave=->=cpal_synth= rename) later as its

- *Timbre data lives in =sawwave/types.rs=* (=Waveform=, =Am=, =Fm=, =Timbre=),
  embedded in =VoiceState= (+ runtime =am_phase=/=fm_phase=). The engine must see
  them to render; the looper imports them.
- *=note_on= takes an explicit =timbre: Timbre=* (not a stateful setter), so loop
  playback can pass each note's stored timbre in C6 without re-churn.
- *Same-pitch collision:* voices stay keyed by pitch (the existing ref-count
  model), so if two sources sound the *same* pitch at once with *different*
  timbres, the first holder's timbre wins (one shared voice). Different pitches --
  the common case -- are unaffected. Reversible (key by source+pitch later) if it
  ever matters; noted, not blocking.
- *Band-limited square/saw* via PolyBLEP (per 6_plan 2.5); sine/triangle naive.

* Remaining roadmap (what's left, with the integration approach I've mapped)
The synth + value math are done and tested. What remains is UI wiring into the
already-built looper. Key facts I confirmed for whoever continues:
- The looper has NO generic window compositor at runtime: =mod.rs::resolve_settings=
  picks specific window *kinds* out of config into cells/rects (=Settings= ->
  =LooperParams= -> =LooperState=); presses go to =state.rs::edo_key= /
  =loops_key=; LEDs are a full =Vec<i32>= per grid from =edo_levels()= /
  =loops_levels(flash_on)=, diffed by =send_diffs=. So adding the editor =
  (1) parse its window in resolve_settings, (2) intercept its rect at the top of
  the relevant *_key, (3) overlay its cells at the end of the relevant *_levels.
- Selection pickers, loop display, copy/undo, remap (fine + group-transpose) all
  already exist in state.rs -> C7 reuses them.
