Yes, mostly. "Chord" as a REASON TO RING can die exactly the way "edit" did:

What this buys, all of which I like:

- The edit carve-out disappears: edited ⊆ sustained becomes universal again,
  and the two-layer selection union in the key handler shrinks.
- A per-voice kill for ONE chord voice appears for free -- the sustain
  toggle above it ends it, which round 2 noted was missing (today only the
  widened clear can end a chord voice, wholesale).
- Erase, the clears, and capture all become uniform: "every voice sounding
  without a finger" with no special cases.

1. *The pedal.* Sustained voices follow the EX-P live; your round-2

2. *Same-pitch coexistence.* Your "Otherwise." ruling: chord voices are
   scenes, not piano keys -- two chord voices may share a pitch, a finger

   requires rebuilding sustain to be per-VOICE rather than per-pitch -- a
   real refactor of the ring/accrete architecture (worth doing if you want
   it, but it is cleaning-phase-sized, not a patch).

** DONE correction in my earlier request : longest phase -> longest period
Each voice at frequency higher than the base (longest) cycle
has its phase recorded
relative to the base cycle, as well as its own position in its own cycle. It
resumes (after the attack slew) at both of those. This way I can guarantee that
everything sounds the same relative to the base cycle.

Unusually, the base cycle starts at phase=0,
rather than wherever in that cycle we were when save happened.
All the others begin wherever they were relative to it and in themselves
when they were saved.
*** DONE claude: the base cycle, one rewind for everything
=chords::snapshot= now picks the LONGEST-PERIOD voice (lowest pitch; ties to
the largest phase) as the base and rewinds the save instant by =dt =
phase_B / freq_B= seconds -- to the most recent start of the base's cycle.
Each voice stores its phase as of that instant (=phase_i - dt * freq_i=, from
the stored pitch's frequency, so a mid-glide save uses the target it will
replay at), which is one number that encodes both "where it was in itself"
and "where it was relative to the base cycle"; the base stores exactly 0.
The factored-pulse phases rewind by the SAME =dt= (one coherent instant),
which also removed the old separate pulse-reference rule. Docs updated
(2_discussion Round 3 note, both readmes, StoredVoice/snapshot comments);
tests rewritten around the octave-pair rewind math. =cargo test
--workspace=: 734 passed, 0 failed.

Refined per chat: ties go to the voice closest to its cycle boundary in
EITHER direction (=min(phase, 1 - phase)=), and accordingly the anchor is
the base's nearest boundary -- =dt= is signed, so a base past half-cycle
advances to the boundary just ahead instead of rewinding nearly a full
