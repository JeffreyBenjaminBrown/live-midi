* verbose
The looper of =monome-looper-58-8-1=, plus *per-note timbre*. Two 16x16 grids: one
plays notes in 58-EDO and edits the *active loop's* timbre; the other records,
plays back, edits loops, and edits the *live* timbre. Defined by
=monome-looper-58-8-1-timbre.toml=; runtime in
=buried/midi_pulse/looper_runtime/=.

This file documents the *layout* -- where every window sits and how the two grids
look folded and unfolded. For the meaning of the timbre parameters, the looper's
own mechanics, and the design rationale, follow the authoritative documents listed
at the end (=6_plan.org=, =7_layout.org=, =monome-looper-58-8-1.org=). A future
writer wanting to build a rig like this one should read those first, then use
this file as a worked example of the result.

** what's new versus the plain looper

This rig is the plain looper (=monome-looper-58-8-1.toml=, documented in
=monome-looper-58-8-1.org=) with two =timbre_editor= windows added. Everything the
sibling doc says about *recording*, *remap*, *copy*, *slots*, and the *loop
display* still holds -- read it for those. Here we add only:

- *timbre* :: everything about how a note sounds except pitch and timing --
  waveform (sine/triangle/square/saw), amplitude, slow AM (depth, frequency,
  shape), and slow FM (depth, frequency). Each *live* note and each *recorded loop
  note* carries its own timbre snapshot (6_plan 2.1).
- *the two timbre editors* :: one =timbre_editor= window kind, two instances,
  *named by what they edit, placed on the opposite grid* (6_plan 2.2):
  - the *loop-timbre editor* (=target = "loop"=) lives on the *edo* grid and edits
    the *active loop's* stored per-note timbre;
  - the *live-timbre editor* (=target = "live"=) lives on the *loops* grid and
    edits the *live* timbre (what fingered edo notes get).
  You edit X's timbre on the *not-X* grid so X stays visible while you tweak it.
- *fold* :: each editor rests *folded* -- a 1-row strip (the runtime starts here).
  Its top-left cell unfolds it to ~7 rows. The two grids differ in how they make
  room (the heart of 7_layout.org):
  - *edo -> occlusion.* The unfolded editor simply draws over the top 7 rows of the
    play grid; the rows beneath are unplayable while covered. Notes never move.
  - *loops -> reflow.* The whole looper stack (slots, transport, copy/undo/remap,
    loop display) sits *below* the live editor and *slides down 6 rows* when it
    unfolds, then back up when it folds.

** overview -- the two grids

Cells are ~(x, y)~, ~(0,0)~ top-left, ~y~ down. Both grids are 16x16. *Both
editors start folded*, so the resting pictures (left) are what you first see;
unfolding (right) is momentary -- you fold back to play.

** details

The detail tree below goes: shared resources first, then each grid's windows in
rig order (which is paint order -- later windows occlude earlier ones).

*** shared resources

**** tuning =main= -- 58-EDO

=[[tunings]] id="main"=, =edo=58=, =x_step=8=, =y_step=1=, =fundamental_hz=80=.
Cell ~(x,y)~ sounds step ~8*x + y + register~; right is +8 steps, down is +1, one
octave is 58 steps. (Same as the plain looper.)

**** sink =saw= -- the polytimbral synth

=[[sinks]] kind="cpal_synth"= (NOT "sawwave" -- the kind was renamed in 6_plan C0;
it can render any of the four waveforms). =sample_rate=48000=, =buffer_frames=128=,
=amplitude=1.0=, =attack_secs=0.003=, =release_secs=0.050=.
Both live play and loop playback emit note events -- each carrying its own timbre --
into this one synth.

The sink amplitude is a *unity pass-through* (1.0): with a timbre editor present the
per-note *gain* row is the volume control (6_plan 2.5), so its top cell -- = 0.15
output, the pre-timbre instrument's level -- is "unity", and the live timbre boots
there. (The plain =monome-looper-58-8-1.toml=, with no gain row, keeps the 0.15 on
the sink instead. Setting both to 0.15 would double-attenuate: the gain row's top
would reach only 0.0225.)

**** =[am.shape]= -- the instrument-wide shape family

=family = "sin_to_square"=. The AM-shape row sweeps the per-note morph *position*
within this family (sine at one end, square at the other). The family is chosen
once here, rig-wide (6_plan 2.5); =tri_to_square= is the other option.

**** =[looper]= -- the looper scalars

| key                  | value | meaning                                                |
|----------------------+-------+--------------------------------------------------------|
| ~clock_bpm~          |   240 | metronome rate (one beat = one cycle); see below       |
| ~clock_duty~         |   0.1 | fraction of each cycle the flashing button stays lit   |
| ~cluster_display_ms~ |   100 | note-ons within this of each other = one column        |
| ~flash_ms~           |    50 | sounding-slot flash half-period (NOT the clock)        |
| ~remap_center~       | (7,7) | the "unison" edo cell for group-transpose remap        |

The *metronome* (=clock_bpm=, 300 = 4x75 -> a 200 ms cycle) is a free-running clock
from program start. It drives three things on the loops grid:
- *transport sync* :: pressing start/stop/play takes effect on the *nearest* cycle
  boundary, so every loop starts and ends on a beat -- its length is a whole number
  of cycles.
- *record quantize* :: a note-on within a *fixed 50 ms* of a boundary is recorded as
  if it started exactly on that boundary (note-offs are left as played). The window
  is fixed (not tempo-derived): it models human timing precision -- a neurological
  constant -- not a musical interval, so it does not shrink as the clock speeds up.
- *transport flash* :: one transport button strobes the cycle -- lit for the first
  =clock_duty= of it (default 0.1 = 10%), dark the rest, the dark->light edge on the
  boundary. A short pulse reads better than a 50/50 blink (the eye is coarser in time
  than the ear); shrink =clock_duty= for a tighter strobe. The lit button is *stop*
  when idle, *start* while recording, *play* while a loop sounds; the other two dim.

**** =[[monomes]]= -- the two grids

=edo= (port 9000, prefix =/looper-edo=) and =loops= (port 9001, prefix
=/looper-loops=), both =select.size = [16,16]=. The runtime hands each rig
monome a distinct unclaimed physical grid in rig order; which physical grid is
which doesn't matter.

*** grid 1 -- edo

**** =edo-grid= (=edo_note_grid=, rect ~[0,0,15,15]~)

The whole-grid 58-EDO play surface, bound to =tuning="main"= and =sink="saw"=. It
also reflects the sounding loop and doubles as the remap pitch-picker -- see
=monome-looper-58-8-1.org= for all of that. Listed first, so the editor and shift
pad draw over it.

**** =edo-timbre= -- the loop-timbre editor (=timbre_editor target="loop"=, rect ~[0,0,15,6]~)

Listed *after* =edo-grid= so it occludes the top 7 rows. Edits the *active loop's*
stored per-note timbre (6_plan 2.4). With a selection on the loop display, setting
a parameter stamps it onto every selected note (works on a stopped loop); with no
selection on a *playing* loop, a held parameter rewrites each note-on as the
playhead reaches it. The per-row range mappings are spelled out explicitly in the
=.toml= (see [[* the timbre editor in detail]]); they are the 6_plan 5 defaults,
written out to exercise the explicit-range rig path rather than relying on
defaults.

**** =edo-shift-pad= (=edo_shift_pad=, rect ~[13,14,15,15]~)

The 3x2 lower-right shift pad. Arrows shift the pitch image by one cell, the two
top corners by an octave. Listed last so it sits on top of the play grid.

| cell    | label | effect                        |
|---------+-------+-------------------------------|
| (13,14) | O-dn  | octave down (-58 steps)       |
| (14,14) | ^     | up: pressed notes -1 step     |
| (15,14) | O-up  | octave up (+58 steps)         |
| (13,15) | <     | left: pressed notes -8 steps  |
| (14,15) | v     | down: pressed notes +1 step   |
| (15,15) | >     | right: pressed notes +8 steps |

The pad overlaps the editor's *unfolded* footprint only in y, never in x, and lives
at the grid bottom, so it is always reachable.

*** grid 2 -- loops

Rig order is: live editor, then the looper stack (slots, transport, copy/undo/
remap, display). The =.toml= rects for the stack are the *unfolded* positions; the
runtime reflows them up by 6 when the editor folds (7_layout, =state.rs::reflow_loops=).

**** =live-timbre= -- the live-timbre editor (=timbre_editor target="live"=, rect ~[0,0,15,6]~)

Same window kind and the same per-row ranges as =edo-timbre=, but =target="live"=:
it edits the *global live timbre* that every fingered edo note picks up. A slot
press recalls a whole saved timbre into the live timbre; =arm= then a slot captures
it. *sustain* and *save-undo* are inert here (they are loop-only). This editor is
the *anchor* the looper stack reflows beneath.

**** the looper stack (reflows under the live editor)

These windows are unchanged from =monome-looper-58-8-1.toml= except that they sit
*lower* (to clear the editor) and *move together* on fold/unfold. Rects below are
the *unfolded* (rig) positions; folded, subtract 6 from every ~y~ (the display's
bottom stays at 15).

***** =loop-slots= (=loop_slots=, rect ~[0,7,15,8]~)

A 16x2 field of slot cells, row-major (32 cells; the transport/copy/remap windows
overlay six of them, so those are unreachable -- "no harm", as in the plain looper).
Active slot = solid, sounding = flash, recorded = dim, empty = dark.

***** transport =loop_control= (overlays the bottom slot row)

| id         | control | rect (unfolded) | does                                  |
|------------+---------+-----------------+---------------------------------------|
| loop-start | start   | ~[0,8,0,8]~     | begin recording into the active slot  |
| loop-stop  | stop    | ~[1,8,1,8]~     | stop the active slot's record OR play |
| loop-play  | play    | ~[2,8,2,8]~     | loop the active slot as the sole one  |

***** copy / remap controls (overlay the slot field)

| id              | kind                   | rect (unfolded) | does                      |
|-----------------+------------------------+-----------------+---------------------------|
| loop-copy       | loop_copy_button       | ~[15,7,15,7]~   | copy a slot: press, from, to |
| loop-remap-mode | loop_remap_mode_toggle | ~[14,8,14,8]~   | fine vs group-transpose   |
| loop-remap-undo | loop_remap_undo        | ~[15,8,15,8]~   | undo the last remap       |

(Behaviour identical to the plain looper -- see =monome-looper-58-8-1.org=.)

***** =loop-display= (=loop_display=, rect ~[0,9,15,15]~)

The 2D picture of the active loop: time left-to-right, pitch bottom-to-top. Its top
row is the column pickers, its left column the row pickers, ~(0,9)~ the
clear-selection corner; the rest is the notes + the remap main area. When the editor
folds, the top jumps to row 3 (rect ~[0,3,15,15]~) and the display grows; the
runtime recomputes note positions for the new height.

** the timbre editor in detail

Both editors are the same =timbre_editor= kind (=looper_runtime/timbre_editor.rs=),
differing only in =target= and which grid hosts them. Every value parameter is a
*radio row*: pressing the k-th cell sets the value, the lit cell shows the current
one, and the number of steps = the rect's width (16 here). Row order is alphabetical
within AM then FM (6_plan 2.6).

*** the control row (unfolded, local row 0)

Local-x layout, left to right: =fold(0) | Sine Triangle Square Saw (1-4) | arm(5) |
sustain(6) | save-undo(7) | timbre slots (8..15)=. On a 16-wide editor that is 8
fixed cells + 8 slots. =sustain= and =save-undo= are active only on the *loop*
target (the edo editor); they are inert on the *live* target (the loops editor).

*** the value rows (unfolded, local rows 1-6) and their rig ranges

Each row's mapping is *tagged* in the =.toml=. =log_range= fixes the endpoints and
scales the steps to the width; =log_factor= fixes the *bottom* and lets the *top*
grow with width (= more cells, higher ceiling); =linear= lerps between min and max.

| row | param        | =.toml= mapping                        | meaning                                                     |
|-----+--------------+----------------------------------------+-------------------------------------------------------------|
|   1 | amplitude    | =log_range= least=0.0009 greatest=0.15 | per-voice gain; top cell = unity = 0.15 output (boot value) |
|   2 | am_amplitude | =linear= min=0.0 max=1.0               | AM depth (more = wider AM; 0 = none)                        |
|   3 | am_frequency | =log_factor= least=0.25 multiplier=2.0 | AM LFO rate, Hz: value(k)=0.25*2^k                          |
|   4 | am_shape     | =linear= min=0.0 max=1.0               | morph position in the =[am.shape]= family                   |
|   5 | fm_amplitude | =log_factor= least=5.0 multiplier=2.0  | FM peak deviation, cents: 5*2^k                             |
|   6 | fm_frequency | =log_factor= least=0.25 multiplier=2.0 | FM (vibrato) rate, Hz: 0.25*2^k                             |

At width 16 the =log_factor= rows reach high (e.g. am_frequency tops near
0.25*2^15 ~ 8 kHz, audio-rate -- welcome, 6_plan [D 2e]).

*** the folded strip (resting, 1 row)

Local-x layout: =fold(0) | 4 quick-timbre cells (1-4) | amplitude across the rest
(5..15)=. The four quick cells start as the four *waveforms* (press = set waveform);
once the first timbre is saved they become the *rolling most-recent-4* saved
timbres. The amplitude row keeps its full =log_range= even though it is narrower
folded (that is exactly why amplitude uses =log_range= and not =log_factor=). The
fold cell itself is lit =Mid= so it is always findable.

** LED scheme (6_plan 2.9)

Roughly four brightness buckets (=Off/Dim/Mid/Bright=): a row's value cell =Bright=,
the rest =Off=; a timbre slot =Off= empty / =Dim= occupied / =Bright= current
(flashing when the live timbre has diverged from it); a toggle =Bright= on / =Off=
off; the fold cell =Mid=. Loop reflection / play lighting on the edo grid is the
looper's own concern.

** run it

#+begin_src sh
cargo run --bin midi_pulse -- monome-looper-58-8-1-timbre
#+end_src

Both 16x16 grids must be connected; both editors come up folded. Ctrl-C blanks the
grids and stops audio. If a grid floods events, see =RUNTIME-NOTES.org=.
