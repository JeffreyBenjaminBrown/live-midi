This rig is written in our TOML-in-org format. The data lives in headlines titled
"PARAM key = value" (values are ordinary TOML syntax); "TABLE name" / "ELEM name"
headlines nest tables and array-of-table elements; any other headline just groups and
documents; and every body (like this one) is a human note the loader ignores. It loads
into the exact same rig as the old .toml did. Format reference (C-c C-o to follow):
[[file:README.org]]
* kmss-drumkit
** PARAM version = 1
See also softstep.toml (the shared SoftStep detection & velocity parameters).
** PARAM id = "kmss-drumkit"
** PARAM title = "KMSS Drumkit"
** shared SoftStep parameters (softstep.toml)
This rig drives at least one SoftStep board. Every board reads its detection and
pressure parameters from the shared file rigs/softstep.toml, not from this rig
file. That shared file holds the onset and release thresholds, the attack window,
the pressure scaling, the contact-bounce and settle debounce guards, and the
de-stick window. Every rig that uses a SoftStep reads the same file, and the
meter reads it too, so one edit there reaches all of them at once.
** ELEM softsteps
A simple drumkit on the Keith McMillen SoftStep (KMSS). Each pedal fires a
one-shot drum sample, PRESSURE-SENSITIVE: on start the runtime switches the KMSS
into tether/hosted mode (over rawmidi via =amidi=), reads its raw pressure-sensor
stream, and scales each hit's loudness by how hard the pad is struck; it restores
standalone mode on exit (including Ctrl-C). Per-pad =gain= below is a scale on top
of that pressure; the strike itself spreads over =gain_db_range= (see softstep.toml).
See learnings/keith-mcmillen-softstep.org for how this works.
Launch under pw-jack so the sampler shares the sound card via PipeWire:
pw-jack cargo run --bin midi_pulse -- kmss-drumkit
See rigs/kmss-drumkit.org for the full reference.
The foot controller. Matched by input-port-name substring (default "SSCOM",
the KMSS's ALSA client name) -- never a hardcoded client number.

** ELEM softstep_windows
The drumkit "window": pedal -> sample. Samples resolve under the top-level
drum-samples/ folder. Pedals are the printed labels (1..9, then 0).
physical layout      left foot          right foot
top  6 7 8 9 0      6 high tom         9 cowbell
bot  1 2 3 4 5      7 low tom          0 crash (electronic)
8 wood block       4 closed hat
1 snare            5 open hat
2 kick             (3 = ditto, the gap between the feet)
*** PARAM id = "kit"
*** PARAM softstep = "feet"
*** PARAM kind = "drumkit"
*** PARAM sink = "drums"
*** PARAM pads = [ { pedal = 1, sample = "snare.wav" }, { pedal = 2, sample = "kick.wav" }, { pedal = 3, ditto = true }, { pedal = 4, sample = "hat.wav" }, { pedal = 5, sample = "open_hat.wav" }, { pedal = 6, sample = "high_tom.wav" }, { pedal = 7, sample = "low_tom.wav" }, { pedal = 8, sample = "wood_block.wav" }, { pedal = 9, sample = "cowbell.wav" }, { pedal = 0, sample = "crash_electronic.wav", gain = 0.5 }, ]
Detection/velocity knobs (debounce, de-stick, thresholds) are shared -- see softstep.toml.
Pedal 3 sits in the gap between the feet -- either foot can reach it. It
retriggers the most recently played sample on ANY pedal in this window, using
THIS press's own velocity against that sample's own pad's static gain trim
("a generalized double-bass pedal"); a ditto press does not itself become "the
last hit" (pad, ditto, ditto repeats the same sample, it does not echo the
ditto). Does nothing if nothing has played yet. See drumkit_runtime/mod.rs
(=PadKind::Ditto=).
