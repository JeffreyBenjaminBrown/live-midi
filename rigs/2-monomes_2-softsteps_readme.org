#+title: Two monomes + two SoftSteps -- reference
#+date: 2026-07-17

The =2-monomes_2-softsteps= rig drives four surfaces at once: two 16x16 monome
grids, each a full 46-EDO play surface, and two Keith McMillen SoftStep (KMSS)
pedalboards that carry the controls that would otherwise cost grid cells --
sustain, the factored pulse, and edit-delete (the factored pulse and
edit-delete are ALSO on each grid, upper right; hands and feet drive the same
state). The two EX-P expression pedals are each grid's volume (see "the EX-P
volume pedals"). No drums: see "what is deliberately NOT here."

* startup

Run it under =pw-jack= so the synth shares the sound card via PipeWire:

#+begin_src sh
pw-jack cargo run --bin midi_pulse -- 2-monomes_2-softsteps
#+end_src

Needs both 16x16 grids AND both SoftSteps connected. The rig pins the grids
by serial (=m256-282= = the older/monobright/LEFT grid, =m0000102= = the
newer/varibright/RIGHT grid) -- see "the two grids" below -- so which physical
grid ends up which is decided by the rig, not by plug order.

Run this ONCE PER LOGIN, on the HOST, before using the rig:

#+begin_src sh
xhost +local:
#+end_src

=xhost= is already installed -- it's in the host's =packages.nix=, so nothing
needs rebuilding. What's missing is running it: =xhost= mutates the running
X server's access list, and that list is rebuilt from scratch every time the
server starts. Installing a package, or rebuilding NixOS, never touches a
running server's access list -- only executing the command, in a terminal
inside the Plasma session (so it inherits that session's =DISPLAY= and cookie),
does. Without it, the container's X connection is refused outright:

#+begin_example
Authorization required, but no authorization protocol specified
#+end_example

The tighter form =xhost +si:localuser:jeff= also works and is the more
targeted grant. Either is per-session -- it does not survive logout, so this is
a once-per-login step, not a once-ever one.

Telling the two SoftSteps apart is by ALSA client name, not by card number:
the older board presents as =SSCOM=, the newer as =SoftStep=. Their card
numbers follow plug order and are not stable -- never hardcode e.g.
=hw:1,0,0=; the rig's =select.name_contains= is what resolves each board, every
run, regardless of plug order.

Here's how to see what's connected:
- SoftSteps: =amidi -l= (they are plain USB-MIDI, so they show up locally).
- Grids: NOT visible as =/dev/tty*= devices in the container -- serialosc runs
  on the HOST and owns the tty, so the container only ever sees a grid over the
  network. Ask serialosc instead: send =/serialosc/list= to =127.0.0.1:12002=
  and read the =/serialosc/device= replies, which carry each grid's serial id.

* glossary

- surface -- one of the four playable devices this rig brings up at once:
  grid A (LOM), grid B (RNM), the old SoftStep (OSS), the new SoftStep (NSS).
- LOM -- grid A, the LEFT / older monome. A Series 256, serial =m256-282=; it
  is monobright, so it cannot dim a single LED and fakes "dim" by flashing
  fast.
- RNM -- grid B, the RIGHT / newer monome, serial =m0000102=. Varibright.
- OSS -- the older SoftStep, ALSA client name =SSCOM=. Nearer to Jeff, not
  rotated: its printed labels read =6 7 8 9 0= (far row) over =1 2 3 4 5=
  (near row).
- NSS -- the newer SoftStep, ALSA client name =SoftStep=. Farther from Jeff
  and physically rotated 180 degrees. The code never learns about the
  rotation -- it only ever binds printed labels -- the rotation just explains
  why the map in "NSS: the factored pulse" looks mirrored. As Jeff reads it (post
  rotation): =5 4 3 2 1= (far row) over =0 9 8 7 6= (near row).
- play grid -- a 16x16 monome, the whole grid a 46-EDO note surface
  (=x_step 9=, =y_step 1=, =fundamental_hz 80=). Pitch rises down and right,
  so "one microtone above" a note is the cell directly below it. Each grid
  has its own voices and its own scroll register.
- scroll pad -- a 3x2 pad at a grid's bottom-right (=[13,14,15,15]=) that
  moves that grid's pitch window: the four arrows shift by one cell, the two
  top corners by an octave.
- waveform strip -- a 4-cell radio at a grid's top-left (=[0,0]..[3,0]=):
  sine / triangle / square / saw, left to right. Each grid's strip sets its
  own timbre (=controls= points at its own =monome=).
- the factored pulse -- a base tempo (seeded 1 Hz; retappable on a grid pad's
  tap cell), applied to each grid through that grid's own =2^a * 3^b= tempo
  factor and its own on/off switch. Driven from either surface: the NSS pedals
  or the grid's own upper-right 3x2 pad, same state. Not "slow AM" -- see "the
  factored pulse" section below for why that name is reserved for something
  else.
- sustain (accrete) -- each grid has its own bank of sustained notes. Here
  it's reduced to two OSS pedals per grid: clear and a momentary accrete
  (hold to add notes, release to stop adding -- nothing is ever un-added by
  releasing). See "OSS: sustain + edit-delete".
- EX-P -- the two M-Audio expression pedals (via the MPC-20 bridge), one per
  grid, each a volume pedal: heel silent, toe unity, fader-law taper
  (exponential + linear splice), slewed. See "the EX-P volume pedals".

* usage

Launch under =pw-jack= so the synth (=cpal_synth=) shares the sound card via
PipeWire:

#+begin_src sh
pw-jack cargo run --bin midi_pulse -- 2-monomes_2-softsteps
#+end_src

Needs both 16x16 grids and both SoftSteps -- see "startup" above for how to
verify what's connected, and "robustness to missing gear" below for what
happens if something isn't. =Ctrl-C= blanks both grids, stops the synth, and
restores both SoftSteps to standalone mode (each is registered for restore
independently, so one board failing to restore never strands the other).

* per-grid layout

The two grids are identical. The whole 16x16 is the play surface, with exactly
four overlays drawn on top -- nothing else lives on either grid; sustain
lives on a SoftStep instead:

#+begin_example
  col: 0   1   2   3   4   5  ...        12    13    14    15
  row 0  [SIN TRI SQR SAW]  .   .   .   DEL    x3    x2    tap   <- edit-delete + factored-pulse pad
  row 1    .   .   .   .   .   .          .    /3    /2    =1    <- factored-pulse pad
   ...                        (46-EDO play cells)
  row 13   .   .   .   .   .   .          .     .     .     .
  row 14   .   .   .   .   .   .          .   8vaDN   UP  8vaUP  <- scroll pad
  row 15   .   .   .   .   .   .          .   LEFT   DOWN RIGHT  <- scroll pad
#+end_example

- The waveform strip (=[0,0,3,0]=), the edit-delete button (=[12,0]=), the
  factored-pulse pad (=[13,0,15,1]=), and the scroll pad (=[13,14,15,15]=)
  occlude the play grid: pressing them re-timbres, deletes the edited voices,
  moves the factored pulse, or scrolls rather than sounding a note. Every
  other cell on both grids is an ordinary 46-EDO play cell.
- The edit-delete button ((12,0), just left of the pad's =x3=; dim at rest,
  bright while pressed) deletes -- silences and ends, the ordinary voice
  ending -- every edited drone on its own grid, and leaves edit mode empty
  (a fingered note just leaves edit mode, ending when its finger lifts).
  Same job as OSS pedals 7/9 (see "OSS: sustain + edit-delete").
- The factored-pulse pad is the six-button block from the kmss rig, brought
  back by request: its factor buttons and ~=1~ drive the same per-grid state
  as the NSS pedals (see "NSS: the factored pulse"), and its tap cell blinks
  the base tempo (all grids' tap cells blink together -- the blink is
  unfactored).
- The scroll-pad corners follow the usual convention: top-left = down an
  octave (notes sound lower), top-right = up an octave; the four arrows shift
  the window by one cell.

* the two grids

The rig pins the grids by serial, not by plug/enumeration order
(=select.id_contains= in the rig): grid A = LOM = =m256-282=, grid B = RNM =
=m0000102=. This matters more here than in other two-grid rigs, because every
SoftStep pedal below targets a monome by name ("clear the left monome") and
the whole layout is spatial -- left buttons drive the left grid. Assigning by
enumeration order instead would let a replug silently swap the grids,
inverting the entire pedal board with no error.

* OSS: sustain + edit-delete

Sustain is momentary only: hold the accrete pedal to add notes to that
grid's sustained set, release to stop adding (nothing already added is
removed by releasing). This rig binds only two sustain pedals per grid (clear
+ accrete) rather than the on-grid four the library also supports --
=needs_holding= and =erase= still exist in the library code, they are simply
unbound here (permanently-on =needs_holding=, in effect). Each grid also gets
an edit-delete pedal: stomp to delete -- silence and end, the ordinary voice
ending -- every edited drone on that grid, leaving edit mode empty; fingered
notes just leave edit mode and end when their finger lifts (the same control
as the grid's own (12,0) button).

| pedal | job                       |
|-------+---------------------------|
|     1 | clear grid A (LOM)        |
|     2 | accrete grid A (momentary) |
|     4 | accrete grid B (momentary) |
|     5 | clear grid B (RNM)        |
|     7 | delete grid A's edit-mode voices |
|     9 | delete grid B's edit-mode voices |

Pedals 3, 6, 8, 0 are free. Left buttons drive the left grid, right
buttons the right grid, matching Jeff's left/right principle. Pedal 8 once held
a global tap tempo; Jeff retired it (he never set a tempo with it), so the base
tempo is a seeded 1 Hz, retappable only on the grid pads' tap cells -- see
"NSS: the factored pulse".

* NSS: the factored pulse

Each grid gets five controls: =x2=, =x3=, =/2=, =/3=, and ~=1~. The board's
middle column is ambiguous under Jeff's left/right rule (both boards sit
between the two grids), so the ambiguity is resolved by distance: the pedal
nearer Jeff drives the left grid (LOM), the farther one drives the right grid
(RNM).

As Jeff reads the rotated board (=5 4 3 2 1= far row, =0 9 8 7 6= near row):

| far row  | 5: x2 LOM | 4: x3 LOM | 3: ~=1~ RNM | 2: x3 RNM | 1: x2 RNM |
| near row | 0: /2 LOM | 9: /3 LOM | 8: ~=1~ LOM | 7: /3 RNM | 6: /2 RNM |

Pedal 8 (middle NEAR) is nearer Jeff, so it is LOM's ~=1~; pedal 3 (middle
FAR) is farther, so it is RNM's ~=1~ -- the near/far rule that resolves the
ambiguous middle column, here applied per grid.

** what these pedals do

- The base tempo is seeded at 1 Hz on bring-up, so the factors multiply
  something from the first press. The tap pedal was retired (Jeff never set a
  tempo with it); the only way to change the base is the tap cell on a grid's
  upper-right pad, and doing so is never necessary.
- Each grid has its own tempo factor =2^a * 3^b= and its own factored-pulse
  on/off switch, moved by that grid's =x2= / =x3= / =/2= / =/3= pedals OR the
  matching buttons on its own upper-right pad (same state; the pad's LEDs
  reflect pedal presses and vice versa) -- so one grid's factored pulse can
  run at, say, 3/2 the rate of the other's, or not at all.
- ~=1~ keeps the existing double-tap dance verbatim: press while the grid's
  factored pulse is off -> turns it ON, keeping the current tempo factor;
  press while it's on -> snaps the tempo factor to unity (back to the base
  1 Hz, unmultiplied); a second press within 400 ms of that one -> turns the
  factored pulse OFF. So from cold: press once to start (at whatever tempo
  factor was dialled in), press again to snap to unity, and a fast third press
  stops it.
- ~=1~ does nothing different in edit mode -- only the multipliers (=x2= /
  =x3= / =/2= / =/3=) are edit controls. See "per-voice edit" below for what
  they do there.

Terminology trap: this is called the factored pulse, never "slow AM" and never
just "the pulse" (to avoid clobbering, say, PWM, or some other future use of
that word). "Slow AM" already names a different, separate mechanism -- the
timbre tremolo (=[[timbres]] abs_am_depth= / =abs_am_hz= / =am_shape=), which morphs
a note's amplitude as part of its waveform, with its own configurable depth,
rate, and shape. The factored pulse is a fixed unipolar triangle in =[0,1]= --
always full swing, no depth knob -- driven by the fixed base tempo and a grid's
tempo factor. Both can be on the same note at once, which is exactly when
you'd need to tell them apart by name.

* the EX-P volume pedals

The two M-Audio EX-P expression pedals are per-grid volume: MPC-20 channel 1
drives grid A (LOM), channel 2 grid B (RNM) -- swap the =monome= values in the
rig if the cabling turns out the other way round. They reach the runtime via
the MPC-20 -> host bridge (run =tools/pedals/bridge.sh= on the HOST; if
its "MPC-20 pedals" port is missing the rig prints a red note at startup and
plays on without them). Not the SoftSteps' own EX-P jacks -- that CC is still
deliberately dropped (=2_discussion= 1a chose the MPC-20 path).

- *The fader law: exponential with a linear splice.* The pedal's reliable
  ~1..119 CC travel maps to a position 0..1. The top 90% of the travel is
  EXPONENTIAL -- dB-linear, covering =curve_remainder_exp_db= (50 dB) up to
  unity at full toe, so equal travel is an equal loudness step -- and the
  first =curve_initial_lin_frac= (10%) fades linearly from exact silence up
  to the exponential's -50 dB floor, because an exponential alone never
  reaches 0. Both knobs are per-pedal in the rig, written out at their
  defaults, and HOT-RELOADABLE: edit them and press =r= + Enter -- the new
  taper is applied through the pedal's current position immediately, no
  pedal movement needed. (Linear was tried first -- numb at the toe, a cliff at the
  heel -- then quadratic; this is how console faders are actually built.)
- *Live and future.* It rescales the grid's sounding voices (drones included)
  and every note struck later, multiplying below the waveform strip's timbre
  amplitude and the synth master volume.
- *Slewed.* Each voice glides toward the pedal position with a ~20 ms time
  constant, per sample, so sweeps sound smooth instead of zipper-stepping at
  CC rate.
- *Absolute and safe.* The position is absolute, so a pedal parked at 0
  recovers; and until a pedal's first CC it contributes unity, so an
  unplugged pedal never mutes its grid.

* LEDs

Play-grid LEDs follow the usual =surfaces_runtime= rules (shared with the
=2-monomes_kmss-drums= rig -- see its readme's "LEDs" section for the full
detail): held notes light bright, reflected across both grids under each
grid's own scroll register; a shared recent-note trail (up to =trails_max= 9
pitch classes) lights dim; the waveform strip shows the selected waveform
bright, the rest dim; the scroll pad's arrows are dim, its octave corners
dark, and it fully occludes the play grid beneath it.

Grid A is monobright and Grid B is varibright. Grid A (=m256-282=) cannot dim
a single LED -- it thresholds any level <= 7 to off -- so its "dim" (unselected
waveform cells, trail, arrows) is faked by flashing the cell on/off fast
(~1/32 duty, ~67 Hz) via whole-quad writes. Grid B (=m0000102=) uses a native
dim level. With many dim cells lit at once the flash slows into mild flicker
on grid A -- an accepted trade.

* robustness to missing gear

This rig brings up whatever is connected and loads around what is not,
rather than refusing to start. On startup it lists, in red, every component
it skipped for a missing dependency, then plays on.

- If one grid is unplugged, the connected grid loads and plays normally (its
  own waveform strip and scroll pad work); the absent grid's SoftStep pedals
  that target it (its OSS clear/accrete pair, its NSS factored-pulse pedals)
  have nothing to act on. Cross-grid LED reflection simply has nothing to
  reflect from the missing side.
- If one SoftStep is unplugged, the other SoftStep's bindings still work; the
  missing board's pedals (its half of sustain, or its half of the factored
  pulse) are simply unavailable. The base tempo is fixed, so nothing depends on
  either board to set it.
- If nothing is connected, the run errors out rather than idling.

* per-voice edit
Sometimes you want to change ONE already-sounding note. Accrete it (so your hands
are free), then edit it in place: it keeps ringing and simply moves.

** the two neighbour gestures
The cells directly above and below a sounding note are its handles. Both are toggles,
neither sounds, and both are geometric -- literally the cell above/below, not "the
pitch one microtone away" -- so they don't move when the tuning changes.

| press          | acts on           | does             |
|----------------+-------------------+------------------|
| the cell BELOW | the note above it | toggle edit mode |
| the cell ABOVE | the note below it | toggle sustain   |

Sustain here is the same sustain the pedals give, just aimed at one note: it joins
the same set, paints the same, and a clear flushes it like any other -- including
notes that never went near a pedal.

A cell with sounding notes on both sides (two notes one cell apart, straddling it)
is ambiguous. Edit wins. That case is rare enough not to matter often, but it is
decided rather than accidental.

A note on the top row has no cell above it, and one on the bottom row none below, so
each loses one of its two handles.

** entering and leaving edit mode
Press the cell directly below a sounding note to toggle that note's edit mode.

Jeff's reason for pinning it below rather than by pitch: "my other fingers can do
either side but my thumb can only reach from below." (They coincide here anyway, since
=y_step = 1= makes the cell below exactly one microtone up.)

An edited note keeps sounding whether or not a finger stays on it -- lift your finger
and it goes on ringing until you leave edit mode. Being edited is its own reason to
ring, alongside a finger and a sustain; a note rings while any of the three holds.
So leaving edit mode silences it only if nothing else was holding it up: a note you
had also sustained keeps going.

To be rid of ALL of them at once there is the *edit-delete* control -- OSS
pedal 7 (grid A) / 9 (grid B), or the grid's own (12,0) button. Unlike the
one-note exit gesture it acts on everything: every edited DRONE is silenced
and ended (the ordinary release ramp), sustains included; the pitches leave
the sustain bank; and edit mode empties -- the grid plays again immediately.
A note a finger is physically holding does not end (a finger's voice is the
finger's to end): it just loses its edit and sustain reasons, so it ends
normally the moment the finger lifts.

Leaving always works, whether or not the note can still be heard. That matters more
than it sounds: anything that silences an edited note (a =clear=, say) would otherwise
strand it -- still dancing, still forcing every press to drag, and un-dismissable
because the gesture that dismisses it needed the sound that just went away.

** dragging a note's pitch
While any note on a grid is in edit mode, that grid stops playing new notes: a
press drags the nearest edited note to the pressed pitch instead, gliding over
=slide_duration_ms= (100 ms). Leave edit mode to play normally again.

- The nearest edited note moves -- one of them. (Contrast the factored pulse
  below, which moves all of them. This is deliberate, and it is worth
  knowing: "in edit mode" picks a different selection depending on which
  parameter you touch.)
- A tie moves the lower note.
- Edit mode belongs to the pitch, so it travels with the note: a dragged note is
  still being edited at its new pitch, and can be dragged again. It also survives
  re-fingering the note.

** what you give up, on purpose
- The cell below a sounding note can never sound.
- You cannot drag a note onto its own exit cell -- that press exits instead. The
  exit gesture and the drag gesture are the same press, and exit wins, because
  otherwise there would be no way out of edit mode.
- A note on the bottom row has no cell below it, so it cannot be edited.

** the diamond dance
Each edited note is marked by a single lit cell turning around it -- above, left,
below, right -- holding each corner 150 ms, so one turn is 600 ms.

- This is local, unlike everything else on these grids. It marks the exact
  cell(s) holding that exact pitch on that one grid: never octave-equivalents,
  never the other grid. (A pitch can occupy two cells here -- with =x_step 9=,
  =(x,y)= and =(x+1,y-9)= collide -- and both dance.)
- It stays in step everywhere. The phase comes from one clock, so every dance
  turns together. That is why a corner that cannot be drawn is skipped but
  still spends its slot: compressing the turn would drift that dance out of
  phase.
- It clobbers a dim trail but yields to a bright note. A trail is decoration; a
  sounding note is information. Without the clobber, a note whose four neighbours
  happened to be trailed would dance invisibly -- exactly when the grid is busiest.
- Expect it to read less cleanly on grid A, whose "dim" is faked by fast flashing.

** off-screen notes
If an edit-mode or sustained note scrolls out of the pitch window, the scroll pad's
octave corner that would bring it back flashes (150 ms on / off). Both corners
flash if there are such notes in both directions.

Only the octave corners ever flash -- never the four arrows -- so a note scrolled off
by less than an octave gets no hint. And one signal covers both edit-mode and
sustained notes, so the LED cannot tell you which kind you are chasing. Both are
Jeff's calls ("I'll understand").

** editing a note's factored pulse
With notes in edit mode on a grid, that grid's =x2= / =x3= / =/2= / =/3= --
pedals and the matching buttons on its upper-right pad alike, they run the
same code -- retune those notes' factored-pulse rate directly and leave the
grid's tempo factor alone. With no note in edit mode, the same controls move
the tempo factor as usual.

- It applies to every edited note on that grid at once.
- It multiplies, so notes whose factored pulse already runs at different rates
  keep their spread: "slower ones continue to be slower than faster ones".
- The factored pulse's phase is kept, so a live note changes slope without a
  click.
- A note struck while that grid's factored pulse was off has none, and
  multiplying cannot start one.
- ~=1~ is never an edit control -- only the multipliers are.

Note the one asymmetry with cycling: turning a grid's factored pulse off never
retroactively touches sounding notes; only the multipliers reach them.

* the on-screen window
Born when the factored-pulse controls left the grid for the feet (a pedal has no
display); kept now that the upper-right pads are back, as the at-a-glance numeric
view of the same state. The window shows, and only shows:

- the base tempo as BPM to one decimal place (the seeded 1 Hz = 60.0 BPM,
  unless retapped);
- each grid's tempo factor as 2^x * 3^y;
- whether each grid's factored pulse is on;
- a blinker at the unfactored base tempo, so it does not move when a tempo
  factor does.

It needs =xhost= (see "startup"). If it cannot open, the instrument says so once
and plays on regardless.

* what is deliberately NOT here

- No drumkit. Neither SoftStep plays samples in this rig.
- No distortion, slide, mono, erase, needs-holding, or feet-accrete toggles --
  all exist in the library (reused by =2-monomes_kmss-drums=) but none are
  bound in this rig. Sustain here is the reduced clear+momentary-accrete pair
  only (see "OSS: sustain + edit-delete").
  (The EX-P pedals used to be on this list -- deferred by 2_discussion 1a --
  but they are volume pedals now; see "the EX-P volume pedals".)
- No tap tempo *pedal*. It was retired (Jeff never tapped), and the base tempo
  is seeded at 1 Hz so nothing waits on a tap. The factored-pulse controls
  live on the newer SoftStep per the vision's "use the softsteps instead of
  the monome for it" -- AND, brought back later by request, on each grid's
  upper-right 3x2 pad, whose tap cell is the one (optional) way to retap the
  base.
