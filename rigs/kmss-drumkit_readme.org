#+title: KMSS Drumkit -- reference
#+date: 2026-06-30

The =kmss-drumkit= rig turns the Keith McMillen SoftStep (KMSS) foot
controller into a simple drumkit: each pedal fires a one-shot drum sample. It is
the first instrument built on the *softstep windowing idiom* -- the KMSS analogue
of the monome =[[monome_windows]]= system (see [[./README.org]]).

This is *v1: get the I/O working*. The sounds (a CC0 TR-808 set) are placeholders
to be refined later.

* glossary

- *KMSS / SoftStep* -- the Keith McMillen foot controller. 10 pedals in two rows
  of five, printed =6 7 8 9 0= (top) and =1 2 3 4 5= (bottom). Background and
  protocol notes: [[../../../learnings/keith-mcmillen-softstep.org]].
- *pedal label* -- the number silk-screened on a pedal (1..9, then 0). This is what
  a rig addresses, *not* a coordinate.
- *softstep window* -- a behavior bound to a SoftStep, the same idea as a monome
  window. Today the only =kind= is =drumkit=.
- *drumkit window* -- maps pedals to one-shot drum samples.
- *cpal_sampler sink* -- the audio output that plays the samples (cpal/JACK, like
  the synth's =cpal_synth=).

* usage

Launch under =pw-jack= so the sampler shares the sound card via PipeWire instead
of grabbing it:

#+begin_src sh
pw-jack cargo run --bin midi_pulse -- kmss-drumkit
#+end_src

Then step on the pedals. =Ctrl-C= (or Enter) stops it; dropping the audio stream
silences it. A headless check that loads samples and binds the device but makes no
sound (no audio device needed):

#+begin_src sh
MIDI_PULSE_NO_AUDIO=1 cargo run --bin midi_pulse -- kmss-drumkit
#+end_src

* the mapping (this rig)

| foot  | pedal | voice                    |
|-------+-------+--------------------------|
| left  |     1 | snare                    |
| left  |     2 | kick                     |
| left  |     6 | high tom                 |
| left  |     7 | low tom                  |
| left  |     8 | wood block               |
| right |     4 | closed hat               |
| right |     5 | open hat                 |
| right |     9 | cowbell                  |
| right |     0 | crash (electronic)       |
| --    |     3 | ditto (repeats last hit) |

Spatially: left foot owns the left of the board (=6 7 8= top, =1 2= bottom); right
foot owns the right (=9 0= top, =4 5= bottom); =3= (bottom-middle) is the gap
between the feet -- fittingly where *ditto* sits, since either foot can reach it.

*Ditto* (pedal 3) is not a sample: it retriggers whatever sample most recently
played on ANY pedal in this window, using THIS press's OWN pressure against that
sample's own pad's static gain trim ("a generalized double-bass pedal") -- not the
pressure the original hit was struck at. It does nothing until something else has
played, and a ditto press never itself becomes "the last hit" (so pad, ditto, ditto
repeats the same sample rather than the ditto echoing itself). See "rig shape"
below for the =ditto = true= pad schema, and =drumkit_runtime/mod.rs=
(=PadKind::Ditto=) for the implementation.

*Pedal 8 is =wood_block.wav=, pedal 9 is =cowbell.wav=.* An earlier arrangement
(mis-transcribed from the original wish list, which said "cowbell" where "wood
block" was meant) put cowbell at 8 and gave 9 =ride.wav= instead, since cowbell
would otherwise have landed at both 8 and 9. That was wrong: 8 is wood block (its
original spot) and 9 is cowbell (its original spot); =ride.wav= drops back out of
the kit. The plain =crash.wav= (the old pedal-8 occupant, a TR-808 cymbal
near-identical to =ride.wav=) also stays out -- pedal 0 still plays
=crash_electronic.wav= (a synthesized, clearly-distinct crash), consistent with the
other KMSS-drums rig. The unused WAV files stay in =drum-samples/=, just
unreferenced.

* rig shape

** the device -- =[[softsteps]]=
Declared once, referenced by =id= from windows -- exactly like =[[monomes]]=.

#+begin_src toml
[[softsteps]]
id = "feet"
select.name_contains = "SSCOM"   # input-port-name substring (default "SSCOM")
#+end_src

The KMSS appears on ALSA as the client "SSCOM" with two ports; the runtime binds
the *performance* port ("SSCOM MIDI 1"), preferring it when several match. The
match is by *name substring*, never the ALSA client number (which changes on every
replug).

** the sink -- =cpal_sampler=
A one-shot sample player. Same cpal/JACK output path as =cpal_synth=.

#+begin_src toml
[[sinks]]
id = "drums"
kind = "cpal_sampler"
sample_rate = 48000      # requested output rate; samples resample to it per-voice
buffer_frames = 128
amplitude = 0.8          # master gain; per-frame mix is clamped to [-1, 1]
#+end_src

** the window -- =kind = "drumkit"=

#+begin_src toml
[[softstep_windows]]
id = "kit"
softstep = "feet"        # -> [[softsteps]] id
kind = "drumkit"
sink = "drums"           # -> a cpal_sampler [[sinks]] id
# detection/pressure knobs (debounce, de-stick, thresholds) are shared -- see softstep.toml
pads = [
  { pedal = 1, sample = "kick.wav" },
  { pedal = 2, sample = "snare.wav", gain = 1.0 },
  { pedal = 3, ditto = true },
  # ...
]
#+end_src

Each pad binds a *pedal label* to either a *sample* -- a filename under the
top-level =drum-samples/= folder (a =sample= may name a subpath, e.g.
=808/kick.wav=, for multi-kit layouts) -- with an optional =gain= (default 1.0;
a per-pad *scale* on top of the strike pressure, not a fixed loudness) -- *or*
=ditto = true=, with no =sample= and no meaningful =gain=: it retriggers the most
recently played sample in the SAME window, using its OWN press's pressure against
that sample's own pad's =gain= trim (see "the mapping" above).

* behavior notes

- *Pressure-sensitive.* On start the runtime switches the KMSS into *tether
  (hosted) mode* -- SysEx over ALSA rawmidi (=amidi=) -- and restores standalone
  mode on exit or Ctrl-C. In tether mode the device streams each pad's 4 pressure
  sensors as Control Changes on channel 0 (CC 40..79; a pad owns 4 consecutive
  CCs). The runtime sums a pad's 4 sensors (0..508) into a continuous *pressure*
  0.0..1.0 (=pressure_full_scale=, 460) and spreads that across =gain_db_range=
  (20 dB) of loudness -- explicitly *not* a MIDI velocity. A pad's =gain= scales
  on top of that pressure ([[../../../learnings/keith-mcmillen-softstep.org]]).
- *Fired at onset, then revised.* A pad fires the instant its sum crosses
  =on_sum= -- so even a one-sample tap counts -- and for =attack_ms= (14 ms)
  after that the decoder keeps watching, ramping the sounding voice up if a
  higher peak arrives. It does not wait out the window before firing.
- *Preset-independent.* Tether mode identifies a pad by its sensor CCs, so the
  kit works no matter which on-device preset is showing. (Standalone mode sends
  Program Changes instead -- no velocity, and simultaneous presses collapse into
  one or none; that is what tether mode exists to avoid.)
- *Foot lifts are real releases.* The decoder reports them, so a pedal can be
  *held*; one-shot samples simply ignore the release.
- *Per-pedal debounce.* A hard stomp can double-trigger one pedal; the shared
  =debounce_ms= (in =softstep.toml=, default 100) suppresses a repeat of the *same*
  pedal within the window. It is per pedal, so two different pedals struck together
  (two feet within ~1 ms) both fire faithfully.
- *Polyphonic.* Hits overlap; a ringing crash keeps sounding under later hits
  (up to a 64-voice pool, then the most-finished voice is stolen).

* validation (rejected at load)

- a pedal outside 0..9;
- the same pedal assigned twice in one window, or claimed by two windows on the
  same device;
- a =softstep=/=sink= reference to an undeclared id, or a =sink= that is not a
  =cpal_sampler=;
- a sample path that is absolute or escapes the samples root (contains =..=);
- a pad naming neither =sample= nor =ditto = true=, or naming both;
- more than one =ditto = true= pad in the same drumkit window;
- a declared softstep that no window uses.

Sample *files* are not checked at parse time (validation is filesystem-free, so
rigs stay unit-testable); a missing WAV errors clearly at launch.

* swapping arrangements

Different drumkit = a different rig, or (later) a different softstep-window
=kind= -- exactly the monome story. To change which pedal plays what, edit =pads=;
to change the sounds, point each =sample= at a different file under =drum-samples/=
(use a subfolder + subpath for an alternate kit), or replace the WAVs in
=drum-samples/=.
