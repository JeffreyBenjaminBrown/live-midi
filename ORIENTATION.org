* the active work: the 2-edogrids pair (the surfaces runtime)
Jeff's daily instrument lately: two 46-EDO play grids + two SoftStep pedal
boards (sustain + edit mode underfoot), two EX-P volume pedals, per-grid
factored pulse, per-voice edit mode, configurable timbres with abs/rel AM+FM.
Two rigs, *identical but for what the NEWER SoftStep does* -- a rename in
2026-07 put that difference in the names (both were once
=2-monomes_2-softsteps=, a name that counted the hardware instead):
- =2-edogrids_ss-accrete_ss-pulse= -- the newer board drives the factored pulse.
- =2-edogrids_ss-accrete_ss-drums= -- the newer board is a TR-808 drumkit
  instead. Jeff never touched the pulse pedals, and the grids' own upper-right
  pads already drive the pulse, so that board was free.
Change one rig's grids and you must change the other's; a test
(=the_two_edogrid_rigs_differ_only_in_the_newer_boards_job=, in =rig.rs=)
fails if they drift.

* build / run / test
#+begin_src sh
cargo test -p edo_surface                    # fast, no hardware
cargo test --workspace                       # everything
pw-jack cargo run --bin midi_pulse -- 2-edogrids_ss-accrete_ss-pulse   # needs the gear
#+end_src
The live crate is =edo_surface=, so that is the =-p= you want; =-p midi_pulse=
tests only the =buried/= legacy crate (the looper/piano/un-12 runtimes and the
=midi_pulse= dispatch binary), which is still where the =--bin= comes from.
Most logic is testable without hardware; do that. Running for real needs the
grids and audio routing (below). Ctrl-C blanks both grids and stops audio.

To exercise the *device layer* (discovery/registration/LED/key) -- or play the
whole instrument -- without real grids and without interrupting a live session,
use the *monome mock*: =cargo run --bin mock_monome= + =MIDI_PULSE_DETECTOR_PORT=.
See [[./MOCK-MONOME.org]]. Parallel-branch workflows: [[./how-to-parallelize-dev.org]].

* operational facts (these otherwise live only in memory)
- *Audio routing*: synths run in the container, where ALSA "default" wasn't wired
  to host PipeWire -- so =cpal= grabbed the raw card and blocked sound. Fixed with
  =~/.asoundrc= (default -> pipewire) + a self-reaping beep hook. Restart a synth
  to pick up routing.
- *Serialosc flood*: if a monome floods or serialosc freaks out, STOP and ask
  Jeff to unplug, restart serialosc, and reconnect -- he's on the host, you're in
  the container and can't.
- *Hardware*: both 16x16 grids must be connected to run the looper for real, and
  you usually can't watch them yourself -- ask Jeff to verify on the grids.
- *Finding the gear from in here.* The two families answer to different tools, and
  the grids are NOT visible as /dev/tty devices in the container -- =ls /dev/ttyUSB*=
  finds nothing even with both grids plugged in and working, because *serialosc runs
  on the host* and owns the tty. Absence there proves nothing. Ask serialosc instead
  (it is reachable thanks to =--network host=):
  #+begin_src sh
  # grids: send /serialosc/list to 127.0.0.1:12002, read the /serialosc/device replies
  amidi -l          # softsteps: plain USB-MIDI, so these DO show up locally
  #+end_src
  The replies give each grid's *serial id* -- =m256-282= (the older, monobright one)
  and =m0000102= (the newer, varibright one) -- which is what rigs pin with
  =select.id_contains=. The SoftSteps distinguish themselves by ALSA client name:
  ="SSCOM"= is the older board, ="SoftStep"= the newer. Their *card numbers follow
  plug order and are not stable* -- never hardcode =hw:1,0,0=.
