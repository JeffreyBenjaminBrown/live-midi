#+title: softstep_meter -- reference
#+date: 2026-07-08

=softstep_meter= is the Rust port of the Python velocity meter
(=code/python/softstep/meter/main.py=): a live per-pad pressure readout for the
SoftStep, driving the *exact same* tether decoder
(=drumkit_runtime/decode.rs::TetherDecoder=, reused via =#[path]=, not
reimplemented) that =kmss-drumkit= plays through. It has no monome/accrete/pedal-
hook code -- it exists purely to watch sensing, hit detection, velocity, and the
ditto pad, so what you see here is what the drumkit would fire.

* usage

#+begin_src sh
cargo run --bin softstep_meter
#+end_src

Add =pw-jack= in front if you turn on the optional audio audition (below). Type
=q= + Enter to quit, or Ctrl-C -- both restore standalone mode on the way out
(=tether::arm=/=TetherSession=, the same restoration path the drumkit uses).

* what it shows

For each pad, in printed-label order (1..9, then 0): a live pressure bar (sum of
its 4 sensors, 0..508, same de-stick as the decoder) with a peak-hold marker, the
last fired velocity, and the resolved gain. A detected hit also appends a line to
a small recent-events log at the bottom (e.g. =pad 1: vel 100 (gain 0.891)=).

*Pad 3 is wired as DITTO*, mirroring =rigs/kmss-drumkit.toml=\='s pedal 3 ("the
gap between the feet"): struck, it repeats the last REAL pad's hit at the ditto
press's OWN velocity, and a ditto press never itself becomes "the last hit" (so
pad, ditto, ditto repeats the ORIGINAL, not the ditto). See =resolve_fire= in
=softstep_meter.rs=, which mirrors =drumkit_runtime::mod::resolve_fire= /
=PadKind::Ditto= / =LastHit= -- replicated rather than imported, since the real
=mod.rs= is tightly coupled to a full =Rig= + sample bank this meter doesn't
have.

* what it does NOT do

- No monome/accrete mirroring, no =PedalHook=, no grids.
- No per-pad sample bank: it identifies a "hit" by its printed label, not a sound.
- No =.org= event-group logger (the Python meter's =logs/pad-<label>/<N>.org=) --
  that stays Python-only.

* optional audio audition

Off by default. Set =SOFTSTEP_METER_AUDIO=1= to play
=drum-samples/snare.wav= via =pw-play= at the resolved gain on every hit -- one
reference sample for every pad (including ditto's echoed gain), same idea as the
Python meter's =audition-sample=. Kept deliberately minimal (a =pw-play=
subprocess, like the Python meter) rather than wiring up the drumkit's
=audio::Sampler= voice pool, since the meter has no per-pad samples to play
through it anyway.

* why the live pressure bar keeps its own sensor shadow

=TetherDecoder= exposes no accessor for its live per-sensor sums -- only
Fire/Revise/Release events from =poll=. The pressure bar needs a continuous
0..508 reading even between hits, so =softstep_meter.rs= keeps a small shadow of
the same raw CC stream (with the same de-stick timing, from
=SoftstepParams::silence_to_zero_ms=) purely for DISPLAY. Hit detection and ditto
resolution always go through the real =TetherDecoder=, never this shadow.
