* EDO piano transformer with monome mapping
** purpose
This is a variant of =edo72_piano_monome= that maps the twelve piano
pitch classes into an arbitrary EDO.

** to start it
*** Connect the keyboard and monome.
*** Start the docker container.
*** In the docker container, from the project root, run
    cargo run --bin edo31_piano_monome
    # or choose a config file:
    cargo run --bin edo31_piano_monome -- 31-loose.toml
    cargo run --bin edo31_piano_monome -- 58-8-1-snap.toml
*** In the host system, run
    ./code/rust/edo31_piano_monome/connect-midi.sh
** monome layout
The grid size is inferred from serialosc's device type. Known sizes:
=monome 128= is 16x8, and =monome 256= is 16x16. The y coordinate
has =y=0= at the top.

The preimage row is currently =y=0=. Its first 12 keys are the pitch
classes C through B from left to right. White-note keys are off at
rest, and black-note keys are dim at rest.

When a key in the EDO map is pressed, the corresponding key in the
preimage row flashes for at least 300 ms, then stays steadily
on until that physical EDO-map key is released. If the pressed EDO-map
key already belongs to the current 12-EDO image, the flashed indicator
is that key's preimage. If the pressed EDO-map key is dark and the
press assigns a 12-EDO preimage to it, the flashed indicator is the
newly assigned preimage.

The EDO map is drawn across the 10 leftmost columns of the physical
grid, below the preimage row. On a 16x16 monome that is
=x=0..9= and =y=1..15=.

The bottom-right key is an undo button. It restores the previous
remap state, including loose/fixed markings.

The only command-line argument is an optional config filename:

  =cargo run --bin edo31_piano_monome -- [CONFIG_FILE]=

Configs live in =code/rust/edo31_piano_monome/config=. If omitted,
the filename defaults to =default=. The app also accepts a config
name without the =.toml= extension.

The sample configs are:

- =31-loose.toml=: 31-EDO, =between_columns=6=,
  =between_rows=1=, loose remapping.
- =58-8-5-snap.toml=: 58-EDO, =between_columns=8=,
  =between_rows=5=, snap remapping.

=default= points to =58-8-5-snap.toml=.

Each key in that left-column map area represents an EDO step, using
local coordinates within the map area:

  =step = between_columns*x + between_rows*y mod edo=

For example, =58-8-5-snap.toml= means moving one key to the right
raises pitch by 8 steps of 58-EDO, and moving one key downward in
space raises pitch by 5 steps of 58-EDO.

The lit EDO steps are the current image of the twelve piano pitch
classes. Initially they are spaced as evenly as possible. For 31-EDO:

  =0, 3, 5, 8, 10, 13, 16, 18, 21, 23, 26, 28=

For 58-EDO:

  =0, 5, 10, 15, 19, 24, 29, 34, 39, 44, 48, 53=

The EDO-map LEDs use three visual priorities:

- Sounding pitches are steady on.
- The current images of C, F and G flash at full brightness.
- The rest of the current 12-EDO image is steady dim, using the
  monome level-brightness API rather than software PWM.

Higher-priority visuals clobber lower-priority visuals on the same
physical key. The preimage row is separate from the EDO-map LEDs.

There are two remap idioms.

In the =loose= idiom, tap a lit pitch to make its 12-EDO/EDO
key-value pair loose. You can loosen multiple lit pitches. If no pitch
is loose, tapping a dark pitch has no effect.

When you tap a dark pitch, the program finds the nearest lit pitch
below it and the nearest lit pitch above it in the ring of integers
mod EDO. If exactly one is loose, that key-value pair moves to the dark
pitch and becomes fixed again. If both are loose, the nearer one moves;
in a tie, the higher one moves. If neither is loose, nothing changes.

In the =snap= idiom, tapping a dark pitch moves the nearest current
image to that pitch. Distance is measured in the EDO ring, not in the
2D monome layout. In a tie, the higher image snaps down to the tapped
pitch and the lower image stays where it is.

The program also tracks the signed lift of each pitch class. For
example, in 31-EDO, moving C from step =0= to step =30= means =-1=,
not =+30=, so outgoing MIDI moves down by one EDO step rather than jumping up
around the octave ring.

** current monome diagnostic
On 2026-05-12 serialosc reported:

  =m0000102, monome 256=

It also reported two device ports for that same id, which matches the
ghost-tty issue described in =code/rust/monome/README.org=. The app
chooses the last reply. If LEDs work but presses do not arrive, restart
=serialoscd= on the host and reconnect the monome.
