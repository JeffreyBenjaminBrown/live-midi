* 31-EDO piano transformer with monome mapping
** purpose
This is a variant of =edo72_piano_monome= that maps the twelve piano
pitch classes into 31-EDO.

** to start it
*** Connect the keyboard and monome 128.
*** Start the docker container.
*** In the docker container, from the project root, run
    cargo run --bin edo31_piano_monome
*** In the host system, run
    ./code/rust/edo31_piano_monome/connect-midi.sh
** monome layout
The grid is 16 columns by 8 rows, with =y=0= at the top.

Each physical key represents a 31-EDO step:

  =step = 6*x + y mod 31=

Moving one key to the right raises pitch by 6 steps of 31-EDO.
Moving one key downward in space raises pitch by 1 step of 31-EDO.

The lit 31-EDO steps are the current image of the twelve piano pitch
classes. Initially they are spaced as evenly as possible:

  =0, 3, 5, 8, 10, 13, 16, 18, 21, 23, 26, 28=

The LEDs use three visual priorities:

- Sounding pitches are steady on.
- The current images of C, F and G flash with a 50/50 duty cycle
  every 50 ms.
- The rest of the current 12-EDO image flashes with a 10/90 duty
  cycle every 10 ms.

Higher-priority visuals clobber lower-priority visuals on the same
physical key.

Tap a lit pitch to make its 12-EDO/31-EDO key-value pair loose. You
can loosen multiple lit pitches. If no pitch is loose, tapping a dark
pitch has no effect.

When you tap a dark pitch, the program finds the nearest lit pitch
below it and the nearest lit pitch above it in the ring of integers
mod 31. If exactly one is loose, that key-value pair moves to the dark
pitch and becomes fixed again. If both are loose, the nearer one moves;
in a tie, the higher one moves. If neither is loose, nothing changes.

The program also tracks the signed lift of each pitch class. For
example, moving C from step =0= to step =30= means =-1=, not =+30=,
so outgoing MIDI moves down by one 31-EDO step rather than jumping up
around the octave ring.
