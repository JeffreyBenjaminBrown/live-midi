This rig is written in our TOML-in-org format. The data lives in headlines titled
"PARAM key = value" (values are ordinary TOML syntax); "TABLE name" / "ELEM name"
headlines nest tables and array-of-table elements; any other headline just groups and
documents; and every body (like this one) is a human note the loader ignores. It loads
into the exact same rig as the old .toml did. Format reference (C-c C-o to follow):
[[file:README.org]]
* monome-looper-58-8-1-mock
** PARAM version = 1
** PARAM id = "monome-looper-58-8-1-mock"
** PARAM title = "Monome Looper 58 8 1 (mock grids)"
** ELEM tunings
---------------------------------------------------------------------------
Identical to monome-looper-58-8-1.toml EXCEPT the two monomes use non-colliding
listen ports (9100/9101 instead of 9000/9001) and distinct prefixes. That lets
this looper run AT THE SAME TIME as a real session against the `mock_monome`
virtual rig:
cargo run --bin mock_monome -- --detector-port 17002
MIDI_PULSE_DETECTOR_PORT=17002 cargo run --bin midi_pulse -- monome-looper-58-8-1-mock
The mock reports two 16x16 "monome 256" grids, so select.size = [16,16] still
assigns them in rig order (first -> edo, second -> loops). See MOCK-MONOME.org.
